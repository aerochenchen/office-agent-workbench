# 会议督办

把会议记录（纪要草稿、录音转写、备忘）收成可流转的**纪要 + 待办台账 + 催办说明**。方法进技能；不做多人协同系统。

## 何时用 / 不用

- **用**：整理纪要；从纪要拆待办并分人；按台账写催办说明。
- **不用**：纯改公文版式（走 `government-document-format`）；多份材料汇编（走 `multidoc-digest`）。

## 输入与产出

```
用户指定的记录文件（.docx / .md / .txt）或文件夹内会议材料
.office-agent/work/meeting-followup/   # 过程摘录（可选）
工作成果/会议纪要.md                     # 按需
工作成果/待办台账.md                     # 按需
工作成果/催办说明.md                     # 按需
```

用户只要其中一环时，只交对应产物；全流程则三者齐全。

## 四步纪律（必须按序）

### Step 1 — 定位材料（Agent，1 步）

确认会议记录路径。缺路径时 `ask_user` **一次**；可用 `workspace_list` 自查。

### Step 2 — 读取记录（工具，1～2 步）

- `.docx`：`workspace_extract`（默认 section 即可）
- `.md` / `.txt`：`workspace_read`

向用户确认会议主题、时间（文中有则用；无则标「待补」）。

### Step 3 — 按需成文（Agent，约 2～5 步）

**A. 整理纪要** → `工作成果/会议纪要.md`

建议结构：

```markdown
# 会议纪要

- 会议名称：
- 时间 / 地点：
- 主持人 / 记录人：
- 出席：

## 议定事项
1. …

## 讨论要点
- …

## 待办摘要
（可与台账交叉引用，此处只列标题级）
```

**B. 待办分人** → `工作成果/待办台账.md`

| 序号 | 事项 | 责任人 | 时限 | 状态 | 备注 |
|------|------|--------|------|------|------|
| 1 | … | … | … | 待办 | … |

硬规则：

- 每行必须有**事项**；责任人或时限不明时填「待明确」，禁止虚构人名或日期。
- 一事一行；不把多个责任人糊成一句无法催办的话。

**C. 催办说明** → `工作成果/催办说明.md`

依据已有台账（优先读 `工作成果/待办台账.md`，否则从纪要提炼）：

- 开头交代依据（哪次会议 / 哪份台账）
- 按责任人或按超期/临近分组列出待完成项
- 语气正式、可转发；不编造完成进度

### Step 4 — 收尾（Agent，1 步）

`finish` 时列出交付路径；提醒责任人/时限为「待明确」的条目需用户补全。

## 步数预算

| 阶段 | 约计 |
|------|------|
| 定位 + 读取 | 2～3 |
| 成文 | 2～5 |
| **合计** | **≈4～8** |

## 硬规则

1. 不虚构出席人员、决议或完成情况。
2. 待办台账缺责任人/时限必须标「待明确」。
3. 催办说明必须能回溯到台账或纪要中的具体事项。
4. 交付在 `工作成果/`；过程文件在 `.office-agent/work/meeting-followup/`。
