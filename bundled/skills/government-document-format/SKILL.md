# 自动化脚本（优先使用）

排版工作已全部自动化。当用户要求对工作区内 `.docx` 做公文排版时，**使用 Office Agent 工具**调用共享脚本，无需按规则手工逐项改样式：

```
run_shared_script
  name: format_gongwen
  args: [<工作区内相对或绝对 .docx 路径>]
```

也可调用本 Skill 内脚本（等价）：

```
run_skill_script
  skill_id: government-document-format
  script: format_gongwen.py
  args: [<文件路径>]
```

输出文件：`<原文件名>_formatted.docx`（与输入同目录）。

### ⚠️ python-docx 多段落操作陷阱

修改 .docx 文件内容（非单纯排版）时，涉及多段落插入/删除的场景存在已知陷阱。详见 `references/python-docx-pitfalls.md`。核心要点：`addprevious` + `reversed()` 模式不可靠，应使用 `parent.insert()` 直接操作 XML 树。

脚本覆盖的功能：页面设置（A4 + 标准页边距）、默认字体与行距（仿宋 3号 + 28.95pt 固定行距）、所有段落统一间距（段前0/段后0/行距28.95pt）、发文机关标志（小标宋红色居中）、标题识别、主送机关、全层级标题字体切换（一级黑体"一、/第一章"、二级楷体"（一）/1.1"、三四级仿宋"1./（1）/(1)"）、正文首行缩进、红色分隔线。

**操作流程**：确认工作区中的 `.docx` → `run_shared_script(format_gongwen, …)` → 告知用户输出路径；印章等需人工复核的项明确提示。

# 角色与任务
你是一名专业的党政机关公文排版员。当用户上传一个 .docx 文件并要求"按公文格式排版"时，你必须自动对文件进行修改，使其严格符合《党政机关公文格式》（GB/T 9704-2012）的所有规定。**优先使用上方自动化脚本完成排版**。
修改时，请保留原文内容，只调整格式。无法自动完成的部分（如印章图像的精确定位）应尽量调整预留位置，并在文档末尾添加批注说明需人工复核。

# 通用规则
- 纸张：A4（宽 210 mm × 高 297 mm）
- 版心：宽 156 mm × 高 225 mm
- 页边距：上 37 mm，下 35 mm，左 28 mm，右 26 mm
- 默认颜色：黑色
- 每面 22 行，每行 28 字，撑满版心（可通过设置文档网格实现，或在段落中固定行距，推荐行距为 28.95 pt 固定值）
- 文字颜色：如无特殊说明，黑色。

### 字体规范一览表

|------|---------|------|---------|

| 一级标题（一、……） | **黑体** | 三号（16pt） | ✅ 已安装 |

### ⚠️ 字体缺失处理（macOS）

macOS 默认缺少以下关键字体，排版前需做字体可用性检测：

1. **方正小标宋简体** → 文件名通常为 `FZXBSJW.ttf` 或 `FZXiaoBiaoSong-B05S.ttf`
   - macOS 无自带替代字体，必须下载安装
   - 临时降级方案：使用 macOS 系统宋体 `Songti.ttc`（仅用于预览，正式公文不推荐）
   
2. **仿宋_GB2312** → 文件名通常为 `FANGSONG.TTF` 或 `SIMFANG.TTF`
   - macOS 无自带仿宋字体，必须下载安装
   - 临时降级方案：使用系统 Songti.ttc 加斜体模拟（仅用于预览）
   
3. **楷体_GB2312** → 文件名通常为 `KAIU.TTF` 或 `SIMKAI.TTF`
   - macOS 无自带楷体字体，必须下载安装
   - 临时降级方案：使用系统 Songti.ttc（仅用于预览）

4. **宋体** → 已安装 `宋体.ttc`（17MB），用于页码

5. **黑体** → macOS 自带 `STHeiti`，可用于一级标题

6. **Times New Roman** → macOS 自带 `Times.ttc`，可用于英文数字

### 字体检测脚本（macOS）

排版前运行以下脚本检测字体是否安装：
```python
import os, glob
required = {
    '方正小标宋简体': ['FZXBSJW.ttf', 'FZXBSJW.TTF', 'FZXiaoBiaoSong-B05S.ttf'],
    '仿宋_GB2312': ['SIMFANG.TTF', 'FANGSONG.TTF', 'simfang.ttf'],
    '楷体_GB2312': ['SIMKAI.TTF', 'KAIU.TTF', 'simkai.ttf'],
}
font_dirs = ['/System/Library/Fonts/', '/System/Library/Fonts/Supplemental/',
             '/Library/Fonts/', os.path.expanduser('~/Library/Fonts/')]
for name, filenames in required.items():
    found = False
    for d in font_dirs:
        if not os.path.exists(d): continue
        for f in filenames:
            if os.path.exists(os.path.join(d, f)):
                print(f'✓ {name}: {f}')
                found = True; break
        if found: break
    if not found:
        print(f'✗ {name}: 缺失！请下载后放入 ~/Library/Fonts/')
```

### 字体安装方法

缺失字体可从以下渠道获取：
- **方正小标宋简体**：方正字库商业字体，需从方正官网或授权渠道获取
- **仿宋_GB2312 / 楷体_GB2312**：Windows 系统自带字体，可从 Windows 系统 `C:\Windows\Fonts\` 拷贝到 macOS
- 安装方法：将 .ttf 文件放入 `~/Library/Fonts/` 目录即可

# 修改步骤

## 1. 页面设置
- 设置纸型 A4，上、下、左、右页边距分别调整为 37 mm、35 mm、28 mm、26 mm。
- 若支持文档网格，设"只指定行网格"，每页 22 行，每行 28 字；否则将默认段落行距设为 28.95 pt 固定值。
- 设置"对称页边距"或普通，页码左右分布按标准（见下）。

## 2. 版头部分（如文档开头有发文机关标志、份号、密级、发文字号等）
### 2.1 份号（如有）
- 份号用**黑体**三号（16pt），阿拉伯数字，长度 6 位，顶格排于版心左上角第一行。
- 如果文档开头存在"份号：000001"之类，保留内容，调整位置、字体、字号。
- 若无，跳过。

### 2.2 密级与保密期限（如有）
- 用**黑体**三号（16pt），顶格排于版心左上角第二行（如仍有份号），或第一行。
- 保留原有"机密""秘密"字样，保密期限数字用阿拉伯数字，如"机密★1年"。

### 2.3 紧急程度（如有）
- 3 号黑体，顶格，根据份号、密级顺序往下排列。

### 2.4 发文机关标志
- 由发文机关全称/规范化简称+"文件"二字组成，或仅用全称/简称。
- 居中排布，上边缘距版心上边缘 35 mm。
- 字体：**方正小标宋简体**（FZXiaoBiaoSong-Simplified），红色（RGB：255,0,0）。
  - 如系统未安装，参见上方「字体缺失处理」安装或使用降级方案。
  - 字号按需（发文机关标志通常为小初 36pt 至一号 26pt，标题为二号 22pt）。
- 如多个机关联合行文，主办机关在前，"文件"二字居右，整体上下居中。
- 如果文档首行为"XXX文件"，将其设为该标志，并应用上述格式。

### 2.5 发文字号
- 位于发文机关标志下空 2 行位置，居中（下行文）。
- 上行文则居左空 1 字，与签发人同行。
- 字体：3 号仿宋。
- 格式：机关代字〔年份〕发文顺序号，年份用六角括号"〔〕"，顺序号不加"第"，不编虚位，后加"号"。如"XXX〔2012〕10号"。
- 查找并修正文档中的发文字号，确保使用六角括号，去掉多余单词。

### 2.6 签发人
- 上行文时需标注"签发人：XXX"。
- 位置：发文机关标志下空 2 行，居右空 1 字。
- "签发人"三字 3 号仿宋，签发人姓名 3 号楷体。
- 多个签发人每行排两个，回行对齐。
- 如果文档中有"签发人"字样，按此调整。

### 2.7 红色分隔线
- 发文字号下方 4 mm 处插入一条通栏红色细线（宽版心，高 0.35~0.5 mm），颜色为红色。
- 若文档已有类似横线，修改为标准线。

## 3. 主体部分
### 3.1 标题
- 位于红色分隔线下空 2 行位置，居中排布，分一行或多行。
- 字体：**方正小标宋简体**，二号（22pt），黑色。
- 多行时排成梯形或菱形，回行时词意完整，间距恰当。
- 将文档中原有标题识别出来，应用此格式。

### 3.2 主送机关
- 标题下空 1 行，居左顶格，回行仍顶格，最后加全角冒号。
- 字体：3 号仿宋。
- 如果主送机关过多导致首页无正文，可将其移入版记（抄送位置，但标注"主送"），并相应调整。

### 3.3 正文
- 主送机关下一行开始，每个自然段左空 2 字，回行顶格。
- 字体：**仿宋_GB2312**，三号（16pt）。
- 英文及阿拉伯数字：**Times New Roman**，随所在段落字号。
- 结构层次序数（均左空 2 字，回行顶格）：
  | 层次 | 格式 | 字体 | 字号 |
  |------|------|------|------|
  | 第一层 | 一、…… | **黑体** | 三号（16pt） |
  | 第二层 | （一）…… | **楷体_GB2312** | 三号（16pt） |
  | 第三层 | 1. …… | **仿宋_GB2312** | 三号（16pt） |
  | 第四层 | （1）…… | **仿宋_GB2312** | 三号（16pt） |
- 遍历所有段落，根据层次标记应用对应的字体和字号。

#### ⚠️ 西式编号检测与转换（关键）
- **问题**：用户文档常见使用西式多级编号（如"2.1"、"3.2"），这些应识别为第二层标题并自动转为国标编号。
- **检测规则**：正则 `^(\d+)\.(\d+)\s+` 匹配的行即为第二层标题（隶属于上一个"X、"第一层标题）。
- **转换规则**：在每个第一层标题下，将匹配到的第二层标题按出现顺序依次转为"（一）""（二）""（三）""（四）"…，应用楷体、首行缩进 2 字符。
- **示例**："2.1 贯通业务流程"→ 转为"（一）贯通业务流程"（楷体），"2.2 引入智能能力"→ 转为"（二）引入智能能力"（楷体）。
- **注意**：第一层标题切换时（如从"二、"到"三、"），编号计数器重置，确保每组内独立编号。

### 3.4 附件说明
- 正文下空 1 行，左空 2 字写"附件："，后标全角冒号，再列附件名称。
- 多个附件用阿拉伯数字顺序号，如"附件：1. XXXXX"，附件名称末不加标点。
- 名称回行时与上一行首字对齐。
- 查找文档中"附件"相关行，按此格式修改。

### 3.5 发文机关署名、成文日期和印章
- **加盖印章的公文**：成文日期右空 4 字，印章红色，下压署名和日期；署名置于日期之上居中，印章顶上距正文或附件说明一行之内。
- **不加盖印章的公文**：正文下空 1 行右空 2 字排发文机关署名，下一行排成文日期，日期首字比署名首字右移 2 字。如日期较长，则日期右空 2 字，署名相应增加右空字数。
- **加盖签名章**：正文下空 2 行右空 4 字加盖签名章，左空 2 字标职务，签名章下空 1 行右空 4 字编排成文日期。联合行文时，先排主办机关职务、签名章，依次向下。
- 日期格式：用阿拉伯数字，年全称，月日不编虚位（如"2012年7月1日"）。
- 识别文档末尾的署名和日期，根据是否存在印章图片决定用哪种格式调整。如果印章仅为占位符，尽量定位准确，并添加批注提醒插入印章。

### 3.6 附注（如有）
- 成文日期下一行，居左空 2 字加圆括号，如"（此件公开发布）"。

### 3.7 附件
- 附件应另页编排，位置在版记之前，与正文连续装订。附件首页左上角第 1 行用 3 号黑体标"附件"及顺序号，第 3 行居中排附件标题。
- 如果文档有独立附件节，按此修改；若附件与正文分离，在附件左上角标注发文字号+"附件"标识。

## 4. 版记
- 版记位于公文末页最下方，由分隔线、抄送机关、印发机关和印发日期组成。
- 分隔线：首条与末条为粗线（0.35 mm），中间为细线（0.25 mm），与版心同宽。末条分隔线与版心下边缘重合。
- 抄送机关：4 号仿宋体，左右各空 1 字，"抄送"后全角冒号，回行对齐，最后标句号。如将主送移至版记，方法相同，但用"主送"字样。
- 印发机关和印发日期：4 号仿宋，左空 1 字印机关，右空 1 字印日期，日期格式同成文日期，后加"印发"二字。
- 在文档末尾寻找或创建版记部分，按此格式化。如无抄送，可省略该行。

## 5. 页码
- 页码用**宋体**（四号 14pt、半角），阿拉伯数字，居于版心下边缘之下 7 mm，左右各放一条一字线（—）。
- 单页页码右空 1 字，双页左空 1 字。
- 版记前的空白页和版记页本身不编页码。附件与正文一起装订时页码连续。
- 设置页脚，插入页码域并调整格式。若文档已有页码，按上述修改。

## 6. 横排表格
- 若存在横排表格，单页码时表头在左侧（订口），双页码时表头在右侧（切口），页码位置不变。

## 7. 其他特定格式（信函、命令、纪要）
- 如果文档内容明显属于信函、命令（令）或纪要格式，按标准第 10 节相应调整（如信函的红色双线、命令的发文标志及令号等）。

## ⚠️ macOS 性能陷阱（python-docx）

- **inline execute_code 读取大 .docx 文件会触发 300s 超时**。必须改用先 `write_file` 写脚本再 `terminal()` 执行的模式（~30s 完成）。
- 示例：`terminal("python3 /tmp/process_docx.py")` 而非在 `execute_code` 沙箱中直接操作。

# 操作注意事项
- 修改完毕后，保留所有原始正文内容，仅改变其样式。
- **字体处理**：排版时优先使用上方「字体规范一览表」中的标准字体。如标准字体未安装，自动降级为 macOS/Windows 替代字体，并在文档末尾添加批注说明使用了哪些替代字体。
- **英文/数字字体**：正文中的英文、阿拉伯数字必须使用 Times New Roman，与中文的仿宋_GB2312 混合编排。python-docx 中可通过 run 级别的字体设置实现中英文分别指定字体（中文字体名 + Times New Roman）。
- 无法直接生成红色印章或特殊字体时，用最接近的系统字体并注明。
- 所有修改完成后，向用户报告已应用的规则清单（含字体使用情况），并指出任何需要人工复核的地方。
