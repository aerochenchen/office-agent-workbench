# 引用标记与参考文献规范

## 锚点（由 ingest.py 发放）

- 格式：`{doc_id}#{sec}`，例如 `d001#s01`、`d012#s03`
- `doc_id`：三位序号，如 `d001`（按扫描顺序稳定编号）
- `sec`：篇内语义单元序号，如 `s01`（从 01 起）

每个语义单元对应 `chunks.jsonl` 中一条记录，字段 `chunk_id` 与锚点相同。

## 正文内联标记（汇总报告必须遵守）

使用**全角方括号**：

```
……完成数字化平台上线，覆盖基层网点 128 个〔d003#s02〕。
```

规则：

1. 一句定量或事实论断至少带一个标记。
2. 同一句可并列多个：`〔d001#s01〕〔d007#s04〕`。
3. 标记中的锚点必须出现在 `chunks.jsonl`（或该主题 `support_citations`）中。
4. 禁止使用半角 `[]`、脚注编号或「据某文件」而无锚点。

审计脚本用正则提取：`〔(d\d{3}#s\d{2,})〕`。

## 卡片（map）中的 citations

`cards/<doc_id>.json` 的每个 `points[].citations` 必须是**本篇**锚点列表，例如：

```json
"citations": ["d005#s01", "d005#s03"]
```

## 参考文献（报告末尾）

| 文档ID | 文件名 |
|--------|--------|
| d001 | 2025年一季度工作小结.docx |
| d003 | 数字化转型专项汇报.docx |

只列报告正文中实际出现过的 `doc_id`。文件名取自 `manifest.jsonl` 的 `filename` 字段。

## 与审计的关系

- **覆盖率**：正文出现的 `doc_id` ∪ cards 中被 merge 采用的来源 vs manifest 成功入库文档。
- **无效引用**：正文标记的锚点不在 `chunks.jsonl` 中。
- **单一来源数据**：`kind=data` 或 `has_data` 且仅一个 citation / 一个 doc_id 支撑时列入风险清单。
