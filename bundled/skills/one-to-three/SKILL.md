# 一文三用

把同一批源材料（或已有汇总稿）编排成**可流转的三件套**：报告正文、汇报提纲、答问口径。本技能是编排器，不做检索底座；缺料明显时先摸底。

## 何时用 / 不用

- **用**：同一批材料要同时出报告、上台提纲、领导追问答问；或只要其中一件且语境是「从材料提炼」。
- **不用**：只要幻灯片硬文件（走 `brief-deck`）；多份粗汇总（可先 `multidoc-digest` 再来本技能）；纯校对/红笔（走 `doc-proofread`）；对照题目查缺（走 `material-gap`）。

## 输入与产出

```
用户指定的材料文件 / 文件夹，或已有 output/汇总报告.md 等
.office-agent/work/one-to-three/     # 过程摘录（可选）
output/报告正文.md                   # 按需
output/汇报提纲.md                   # 按需
output/答问口径.md                   # 按需
```

用户只要其中一环时，只交对应产物；全流程则三者齐全。若已有 `multidoc-digest` / 写作产物，优先复用，避免重复通读。

## 四步纪律（必须按序）

### Step 1 — 定位材料（Agent，1 步）

确认源材料路径或已有报告路径。缺路径时 `ask_user` **一次**；可用 `workspace_list` 自查。  
材料明显零散且题目不清楚时，建议用户先跑 `material-gap`，或在本轮文首列出「已知缺口」后继续。

### Step 2 — 读取与对齐（工具，1～3 步）

- `.docx`：`workspace_extract`（section 或 paragraph）
- `.md` / `.txt`：`workspace_read`
- 已有汇总：直接读 `output/` 下相关稿

对齐：文种/题目、受众（内部汇报 / 对上）、篇幅预期（用户未说则报告偏中篇、提纲 8～12 页量级）。

### Step 3 — 按需成文（Agent，约 3～6 步）

**A. 报告正文** → `output/报告正文.md`

建议结构：

```markdown
# （题目）

## 一、背景与依据
## 二、主要情况 / 进展
## 三、问题与风险
## 四、下一步建议
```

- 分段有据；定量必须带来源路径或页/段提示，否则写「待核实」
- 不编造未出现在材料中的结论

**B. 汇报提纲** → `output/汇报提纲.md`

面向做成幻灯片，建议：

```markdown
# 汇报提纲

- 场合 / 时长预估：
- 页数建议：

## 页序
1. 封面：（标题）
2. 目录 / 汇报脉络
3. …（一页一意；每页 3～5 条要点）
N. 结语 / 请示事项
```

硬规则：一页一意；每页标题可直接用作幻灯标题；要点短句，勿大段粘贴报告。

**C. 答问口径** → `output/答问口径.md`

```markdown
# 答问口径

| 可能追问 | 建议答法 | 依据（材料路径或「待核实」） | 风险提示 |
|----------|----------|------------------------------|----------|
| … | … | … | … |
```

- 至少覆盖：数据怎么来的、进度为何慢/快、与上次口径是否一致、下一步谁负责
- 材料没有的事实不得编造；标「待核实」并写建议补什么

### Step 4 — 收尾（Agent，1 步）

`finish` 列出交付路径；若用户还要 PPT/讲稿，提示继续用 `brief-deck`（可直接吃 `output/汇报提纲.md`）。

## 步数预算

| 阶段 | 约计 |
|------|------|
| 定位 + 读取 | 2～4 |
| 成文 | 3～6 |
| **合计** | **≈5～10** |

## 硬规则

1. 三件套口径一致：提纲页序与报告章节、答问依据相互不打架。
2. 禁止无出处定量；答问禁止虚构事实。
3. 交付在 `output/`；过程文件在 `.office-agent/work/one-to-three/`。
4. 需要正式排版 Word 时，正文可再交 `government-document-format`；需要上台幻灯时交 `brief-deck`。
