## 二、版式参数（脚本内置，勿改）

| 项 | 值 |
| --- | --- |
| 纸张 | A4 纵向，纸张代码 9 |
| 页边距 | 左/右 1.4cm，上 1.5cm，下 1.3cm |
| 列宽 A/B/C/D | 2.6 / 2.6 / 6.8 / 6.2 cm（四项合计 18.2cm，勿随意改） |
| 缩放 | 宽度 1 页，高度自动（不压缩字号） |
| 顶端标题行 | `$7:$8`（第 2 页起自动重复） |
| 分页 | 按维度组边界自动切分，避免合并单元格被拆页 |
| 页数 | 通常 2 页（第 1 页：维度一、二；第 2 页：维度三、四 + 结论签字） |

行高由脚本按字数估算，不是手工设定；改字数会改分页，**不要手调行高**。

## 三、JSON 输入结构

```json
{
  "meta": {
    "regulation_name": "《××管理办法（试行）》",
    "review_method": "meeting",          // meeting=审查会  self=自查
    "review_date": "2026-10-20"
  },
  "items": [                             // 必须 22 条，顺序固定对应要点 1—22
    {"conclusion": "符合",     "opinion": "一句肯定，可省"},
    {"conclusion": "基本符合", "opinion": "现象 + 建议"},
    {"conclusion": "不符合",   "opinion": "条款定位 + 问题 + 改法"}
  ],
  "other_opinions": ["1.…", "2.…", "3.…"],
  "result": "fail",                      // pass=审查通过  fail=审查不通过
  "signoff": {
    "dept_head": "",
    "members": [
      {"name": "张三", "unit": "办公室", "sign": "", "date": "2026-10-20"}
    ]
  },
  "pending_inputs": ["待补材料1", "待补材料2"]
}
```

- `items` 顺序即要点顺序，不要重排。要点原文在 `assets/review_points.json`
- `conclusion` 取值：`符合` `基本符合` `不符合` `不适用` `待补`
- `result` 判定规则见 SKILL.md「定结论」

## 四、命令

在文书通里用 `run_skill_script` 调用，不要让用户自己跑 Python。工作目录是打开的材料文件夹。

```
run_skill_script
  skill_id: regulation-pre-review
  script: build_report.py
  args: [
    ".office-agent/work/regulation-pre-review/review.json",
    "-o", "工作成果/《××办法》发布前审查报告.xlsx",
    "--draft", "工作成果/《××办法》审查底稿.md"
  ]
```

- 脚本只出 xlsx 和审查底稿。需要 PDF 时，打开 xlsx，用 Excel 或 WPS 另存
- 输出目录不存在会自动创建
- stdout 是 JSON：`ok`、`xlsx`、`draft`、`items`

## 五、改模板

- 只改要点文字 → 改 `assets/review_points.json`，脚本自动适配行高与分页
- 改列宽 → 调 `scripts/build_report.py` 的 `COL_CM`，四项相加保持 18.2cm；D 列（结论）窄于 5.5cm 会让意见栏行数翻倍，直接溢到第 3 页
- 改字号 → `BODY_PT`；改到 9pt 以上容易溢到 3 页
- 单条意见超 70 字会拖长表格；优先精简措辞，不要靠缩字号硬塞
- 要点数量变化（如上级下发新版本）→ 同步改 `review_points.json`、脚本行号区段（`r = 9 + idx`、`A31`、`A35` 起）
