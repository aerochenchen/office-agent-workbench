## 一、一句话结论

文书通具备**结构性安全优势**（数据全程不出内网、桌面单机形态、本地大模型），经对标国家标准与业界权威清单的自评估，未发现不可接受的安全阻断项；本次自评中发现并已封堵 2 项高危风险（脚本凭据泄露、审计日志明文）与 1 项中危风险（非回环绑定强制 token 硬校验），其余残留风险均可在部署阶段收敛；**建议在限定范围内部开展试点**。

## 二、安全定位优势（先讲清"为什么可以放心用"）

| 优势 | 说明 | 证据 |
|---|---|---|
| 数据全程不出内网 | 大模型本地部署，文档处理、会话、审计日志全部在内网闭环，无任何公网回传 | `gateway.py` 仅连配置的 `api_base`，且经 host 白名单校验 |
| 桌面单机形态 | 不是公网服务，攻击面远小于在线 SaaS；API 仅监听 localhost | `app.py` `/shutdown` 强制 localhost；CORS 仅允许 Tauri 壳来源 |
| 已建安全基线 | 权限三档确认、脚本路径约束、Zip Slip 防护、配置脱敏、CSP/CORS 收紧、本机 API token、审计落库、非回环绑定强制 token | 设计 §10.3 验收 A1–A8 多数已达标；Runtime pytest 171 passed |
| 工具调用可追溯 | 每次工具调用落审计库，含 turn_id 贯通 | `audit.py` + `app.py` `_prepare_chat` 注入 |

## 三、评估方法与工具

### 3.1 评估执行平台与国标依据

**评估执行平台**：本次安全自评估由开发方借助两款国产 AI 编程工具协助执行——

- **字节跳动 Trae**（AI 原生代码编辑器）：负责项目结构提取、自动化安全测试用例编写与执行（pytest 171 项案例）、bandit/pip-audit 扫描调度、以及审计库配置脱敏与脚本环境变量剥离的代码级修补与验证。
- **腾讯云 CodeBuddy**（代码助手）：负责安全架构分析、风险清单梳理与定级、OWASP Top 10 for LLM 对标、国家标准对照表编制、以及安全自评估报告与汇报材料的撰写组织。

源代码审查阶段调用**月之暗面公司开源的 Kimi K3 大模型**（2.8 万亿参数，2026 年 7 月发布）对项目全部核心源代码进行逐文件安全分析，识别潜在漏洞、危险调用及逻辑缺陷。

关键安全结论由开发方本人按**附录 B 清单**逐项人工核验后签字确认，确保 AI 辅助结论的可信度与可追溯性。

## 四、风险清单与封堵情况

分级：**H=高（已封堵）/ M=中 / L=低**

| ID | 风险 | 严重度 | 证据 | 状态 | 封堵措施 |
|---|---|---|---|---|---|
| H1 | 脚本网络隔离为软约束：`build_script_env` 仅清代理 env，Python `socket`/`urllib` 可直连任意主机 | 高 | `script_policy.py`；实测 `socket.create_connection` 可达 | **残留-需部署收敛** | 代码层无法可靠硬隔离（脚本可用 ctypes 绕过）；**部署要求**：OS 级网络隔离（Linux `unshare -n` / Windows 防火墙出站禁 python.exe / macOS `sandbox-exec`），见第七节 |
| H2 | 脚本继承父进程全部 env，可窃取 `OFFICE_AGENT_API_TOKEN` 等凭据 | 高 | `script_policy.py` `env = dict(os.environ)`；实测脚本读到 token | **已封堵** | `build_script_env` 增加敏感 env 黑名单，剥离名字含 TOKEN/KEY/SECRET/PASSWORD/CREDENTIAL/AUTH 的变量；新增测试 `test_build_script_env_strips_sensitive_credentials` |
| H3 | 审计日志记录全量 args，`workspace_write` 的 `content`（公文全文）以明文落库 | 高 | `audit.py` `json.dumps(args)` | **已封堵** | `audit._redact_args` 对 content/api_key/token/password 等字段脱敏（content 只记长度，凭据完全遮罩）；新增测试 `test_audit_log_redacts_sensitive_args` |
| M4 | `config.json` 明文存大模型 `api_key` | 中 | `app.py` `save_config` | 残留-部署收敛 | GET /config 已脱敏；**部署要求**：用 OS 文件权限（chmod 600 / ACL）保护 config.json；后续可接入系统 keychain |
| M5 | 同机 API token 经环境变量传递，同用户进程理论上可读 | 中 | `auth.py` | 残留-可接受 | 内网单机桌面可接受；同机若已被恶意软件驻留则威胁模型已超出本软件职责 |
| M6 | 默认 `api_base` 指向公网 deepseek，与内网部署定位不符 | 中 | `app.py` `DEFAULT_CONFIG` | 残留-部署必改 | **部署要求**：安装后首屏必须改为本地大模型地址；可在打包阶段把默认值改空以强制配置 |
| L7 | `relocate_write_path` 遇 `..` 直接返回，依赖后续 `workspace.resolve` 兜底 | 低 | `tools.py` | 可接受 | 最终 `relative_to(root)` 校验仍拦截越界；逻辑冗余，非漏洞 |
| L8 | `_run_python` timeout=600s 较长 | 低 | `tools.py` | 可接受 | 有 timeout 兜底；可按需调短 |
| L9 | bandit 报 SHA1（doc_io.py file_sha1）High | 低 | `doc_io.py:88` | 误报 | SHA1 用于文件去重指纹，非密码学用途；可加 `usedforsecurity=False` 标注消除告警 |
| L10 | 审计 sqlite 无轮转/清理 | 低 | `audit.py` | 运维项 | 长期运行需定期清理；非安全漏洞 |
| M11 | runtime 支持 `--host` 改绑；若绑 `0.0.0.0` 且未设 token，等价于开放的内网远程调用服务（可驱动写文件/跑脚本） | 中 | `__main__.py`、`auth.py` | **已封堵** | 代码层硬校验：`assert_bind_safety` 在启动时检查，绑非回环地址（含 `0.0.0.0`/`::`/内网 IP/域名）且未配置 `OFFICE_AGENT_API_TOKEN` 时**拒绝启动**；无法解析的域名按非回环处理（安全优先）；新增 14 个测试用例覆盖 |
| M12 | Skill 禁网 AST 校验仅覆盖 `scripts/*.py` 顶层 import，`__import__`/`importlib`/子目录脚本可绕过 | 中 | `skill_validate.py` | 残留-部署收敛 | 与 H1 同一收敛：OS 级网络硬隔离为最终兜底；试点期 Skill 安装来源由管理员统一审核 |
| M13 | 无 Prompt 注入技术检测：恶意文档内容可诱导模型发起高危工具调用 | 中 | 全局 | 残留-缓解 | 权限门默认 `cautious` 需人工确认；试点期审计周复核；`trust_workspace` 模式下不处理不可信来源文档 |

## 七、残留风险与部署要求（试点准入条件）

以下为开展试点前**必须**满足的部署配置：

1. **网络硬隔离（收敛 H1）**——三选一：
   - Linux：runtime 进程以 `unshare -n` 启动（无网络命名空间）
   - Windows：防火墙出站规则禁止 `office-agent-runtime.exe` / python.exe 联网（仅允许配置的本地大模型 host）
   - macOS：`sandbox-exec` 禁止出站（试点机通常 Windows，此项可选）
2. **本地大模型配置（收敛 M6）**：安装后首屏 `api_base` 必须改为本地大模型地址，不得保留默认 deepseek 公网值。
3. **config.json 文件权限（收敛 M4）**：`chmod 600`（Linux/mac）或 ACL 限制仅运行用户可读（Windows）。
4. **权限模式默认 cautious**：试点期建议默认 `cautious`（每次写/跑脚本确认），熟悉后调 `standard`。
5. **固定 loopback 监听（M11 已代码层强制）**：自本版本起，绑非回环地址且无 token 时 runtime 直接拒绝启动；安装与启动脚本仍不得携带 `--host` 参数，试点机逐台核验。
6. **试点范围限定**：首批 3–5 名用户、非涉密公文、专人运维。

## 九、自评估局限性

- 本评估为开发方自评，**不替代第三方测评**。
- 代码审查与告警研判使用 AI 辅助分析完成；涉及安全结论的关键控制由开发方本人按附录 B 逐项人工核验签字后生效，未完成核验前本报告结论不作为试点依据。
- 证据基于源码审查（含 AI 辅助分析）+ 本地扫描 + PoC 实测；**未**在目标 Windows 机关环境实测、**未**做完整渗透测试。
- 残留 H1（网络硬隔离）依赖部署配置，需在试点准入时逐机核验。
- 报告中测试数与扫描结果均可在开发机一键复现（命令见第四节末），复核时发现环境差异（如缺 xlwt 导致 155+2 skipped）以该节说明为准。

## 十、结论

文书通经对标 GB/T 45654—2025 与 OWASP LLM Top 10 2025 的自评估，**未发现不可接受的安全阻断项**；2 项高危、1 项中危已封堵并回归验证（Runtime pytest 171 passed）；残留风险均可在部署阶段通过配置收敛。**建议在满足第七节部署要求的前提下，开展 3–5 人、2–4 周的有限范围内部试点**，试点期内完成第三方渗透测试后转正式使用。
