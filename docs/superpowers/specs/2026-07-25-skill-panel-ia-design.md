---

## 1. 目的与问题

### 1.1 目的

把技能相关能力按使用频率拆开：右侧栏只回答「当前 Agent 会用哪些技能」；装/卸/开/关/导入进入独立「技能管理」，降低窄栏信息过载与误触卸载。

### 1.2 现状问题

- 每张技能卡同时露出简介、增强标记、**卸载**、**启用开关**，主次颠倒。
- 卸载为低频、破坏性操作，却与开关同等权重。
- 右侧栏同时充当「能力目录」与「包管理器」，和「精炼底座 + 选装 Skill」心智不符。

---

## 2. 已确认决策

| 决策 | 结论 |
|------|------|
| 组织方式 | **使用 / 管理分离**：右栏 ≠ 管理器 |
| 右栏内容 | **仅展示已启用（`enabled=true`）技能** |
| 右栏交互 | **纯展示**：无开关、无卸载、无 `⋯` 快捷操作 |
| 底栏主按钮 | 文案由「导入技能」改为 **「技能管理」** |
| 管理界面 | 覆盖：总览、启用/停用、导入（含校验预览）、卸载、刷新 |
| 改状态路径 | 开/关/卸/导入 **只在技能管理内**完成；右栏随状态刷新 |

---

## 3. 信息架构

```
┌─ 右侧栏「技能」────────────────────────────┐
│  标题：技能                                 │
│  列表：仅 enabled 技能（名称 + 可选角标）    │
│  空态：说明 + CTA「技能管理」                 │
│  底栏：[ 技能管理 ]                         │
└────────────────────────────────────────────┘
              │ 打开
              ▼
┌─ 技能管理（抽屉 / 居中面板）─────────────────┐
│  分区：预置 | 已导入（或 已启用 | 已停用）     │
│  行：名称、简介、版本、增强/内存、开关、卸载   │
│  顶/底：导入（文件夹 / zip）、刷新、关闭      │
│  子流程：导入预览（校验 errors/warnings）     │
│  子流程：卸载确认                            │
└────────────────────────────────────────────┘
```

对话区、工作区、设置页职责不变。技能管理是壳层模态/抽屉，不是新路由页（首版）。

---

## 4. 界面规格

### 4.1 右侧栏（纯展示）

**展示字段（每项）：**

- 显示名（`display_name` 或 `name`）
- 若 `tier=heavy`：小角标「增强」（可 `title` 提示建议内存）
- **不展示**：长描述正文（可选：悬停 `title` 显示完整 description，避免占高）
- **不展示**：开关、卸载、刷新（刷新仅管理内）

**列表数据：** `skills.filter(s => s.enabled)`，顺序与 Runtime 列表一致即可。

**空态（无任何已启用技能）：**

- 文案大意：暂无启用中的技能；可在技能管理中启用或导入。
- 主按钮/链接：打开「技能管理」。

**顶栏：** 保留「技能」标题；**去掉**「刷新」（或极弱化为管理入口，首版直接去掉）。

**底栏：** 单一主操作「技能管理」。浏览器模式若不能选文件导入，管理页内导入入口按现逻辑降级/隐藏，但开关/卸载/总览仍可用（若 Runtime 可达）。

### 4.2 技能管理界面

**容器：** 居中面板或右侧抽屉（实现自选；需有明确关闭与 Esc）。遮罩点击关闭可保留，与现有 preview 一致。

**总览：**

- 展示全部已安装技能（含停用）。
- 建议分组（首版二选一，推荐 A）：
  - **A.** 「已启用」/「已停用」
  - **B.** 「预置」/「已导入」（预置识别：seed/bundled 来源标记——若 Runtime 暂无字段，首版可用「已知预置 id 列表」或仅文案区分后续再补 API）

**每行能力：**

| 能力 | 行为 |
|------|------|
| 启用开关 | 调用现有 `setEnabled`；成功后刷新列表；右栏同步 |
| 简介 / 版本 / 增强提示 | 展示，重量技能保留内存建议 |
| 卸载 | 打开确认框；文案强调不可恢复；成功后刷新 |
| 导入 | 文件夹 / zip·md（现有 pick + inspect + 校验预览 + 仅安装 / 安装并启用） |
| 刷新 | 重新 `listSkills` |

**导入预览 / 卸载确认：** 作为管理界面的子对话框，逻辑复用现有校验与错误展示；有 validation errors 时禁用安装。

**预置技能卸载（产品口径）：**

- 管理列表尽量标注「预置」。
- 卸载确认增加一句：预置技能卸载后可经重新 seed/重装包恢复（按现行 Runtime 行为如实写，不承诺「一键恢复」除非已实现）。
- **不做**「禁止卸载预置」硬限制（除非后续产品要求）；靠标注 + 确认降低误触。

---

## 5. 状态与同步

1. 管理页内任何 enable/install/uninstall 成功 → 调用现有 `onRefresh` / 重新拉列表。  
2. 右栏仅派生自最新 `skills` 的启用子集，无本地第二份状态。  
3. 管理页打开期间若外部刷新，以最新列表为准。

---

## 6. 非目标（本规格不做）

- Skill 本地许可证 / 机器码授权 UI  
- 公网技能市场、在线更新  
- 按工作区分别启用（设计里「全局或按工作区」——首版保持**全局**启用，与现 Runtime 一致）  
- 恢复左侧文件树或改动对话区  
- Runtime 新 API（除非补「预置」标记时再开一小项）

---

## 7. 验收标准

1. 右栏**看不到**停用技能；**没有**卸载按钮与启用开关。  
2. 底栏为「技能管理」，可打开管理界面。  
3. 管理内可完成：查看全部、开/关、导入（含校验拦截）、卸载确认、刷新。  
4. 关闭某技能后，右栏该项消失；再启用后出现。  
5. 全部停用时出现空态与进入管理的 CTA。  
6. 现有 skill 相关 Runtime 测试不因本改动而要求改契约；桌面 `npm test` / `npm run build` 通过。
