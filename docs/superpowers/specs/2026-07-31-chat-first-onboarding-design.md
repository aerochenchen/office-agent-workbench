# 文书通 · 对话优先入门与用词统一

| 项 | 内容 |
|---|---|
| 状态 | 已批准（2026-07-31） |
| 日期 | 2026-07-31 |
| 版本 | V1.0 |
| 范围 | 桌面壳用户可见文案、欢迎/空态、发送与文件夹入口权重、未选文件夹时的对话路径；Runtime 沙箱语义不变 |
| 受众假设 | 机关/办公室办事员（几乎未接触 IDE） |
| 对照 | 现行 `ChatPanel.tsx`、`SessionList.tsx`、`guide.ts`、`WorkspaceTree.tsx`、`SettingsModal.tsx` |

---

## 1. 目的与问题

### 1.1 目的

1. **用词统一**：用户只面对一个具体概念——「文件夹」，降低「项目 / 文件夹 / 工作区」并存造成的理解成本。
2. **对话优先入门**：打开产品后第一注意点是对话框；发送为唯一主题绿 CTA。用户凭直觉先聊几句，约 3～5 轮内理解软件能做什么、大概怎么做、还有可探索空间；需要读写本机材料时再引导打开文件夹。

### 1.2 现状问题

- 同一沙箱根目录在 UI 中交替称为「工作区」「文件夹」「项目文件夹」，办公用户易困惑。
- 未打开文件夹时输入与发送被禁用，欢迎页主 CTA 为「打开文件夹」，违背「先聊天再办事」的直觉。
- 「工作区」偏 IDE 黑话，不适合作为对机关用户的主界面用语。

---

## 2. 已确认决策

| 决策 | 结论 |
|------|------|
| 目标用户 | **A**：机关/办公室办事员 |
| 用户可见主词 | **仅「文件夹」**；代码层可继续使用 `workspace` |
| 禁用对用户露出 | 「工作区」「项目」「项目文件夹」 |
| 权限档文案 | 「信任工作区」→ **「信任此文件夹」** |
| 主 CTA | **发送**为唯一主题绿；打开文件夹为侧栏次要/幽灵按钮 |
| 未选文件夹时输入 | **可输入、可发送**（运行时就绪即可） |
| 入门带法 | **先 A**：模型连通时用自然对话接住用户原话并引导；约 3～5 轮为目标，不强制凑满 |
| 模型未连通 | **固定文案**引导去设置配置 API Key / 地址 / 模型，不调用模型 |
| 未选文件夹能力边界 | 可介绍、用法、纯文本讨论；**不读不写本地文件、不跑依赖文件夹的技能** |
| 会话持久化（第一期） | 未选文件夹：允许聊天，会话可不落盘或仅内存；「新建对话」禁用并提示打开文件夹后可保存。选中文件夹后沿用现有按文件夹列会话 |
| 不做 | 多步强制向导弹窗；必须满 N 轮才能选文件夹；主界面同时塞设置/技能/文件夹三件大事 |

## 3. 用词规范

| 场景 | 用户可见文案 |
|------|----------------|
| 打开 / 更换 | 「打开文件夹」「更换文件夹」 |
| 侧栏路径标签 | 「当前文件夹」 |
| 边界说明 | 「文书通只在你选的文件夹内读写」 |
| 权限档 | 「信任此文件夹」 |
| 附件 / 报错 | 「文件夹内…」；「请先打开文件夹」 |
| 阶段提示 | 「查看文件夹…」（原「查看工作区…」） |

引导与设置「使用说明」中凡「工作区 / 项目文件夹 / 本项目」一律改为文件夹口径；`guide.ts` 等用户文案源同步更新。

## 4. 打开后的对话状态机

```text
用户点发送
  ├─ 运行时未就绪 → 短提示：稍等或重启应用
  ├─ 模型未连通（无 Key / 校验失败 / 请求失败）
  │     → 固定文案：需配置 API，指向「设置」
  │     → 不调用模型；配好后再发一句即可继续
  └─ 模型已连通
        ├─ 未选文件夹 → 正常对话 +「入门策略」系统约束
        └─ 已选文件夹 → 正常办事模式（现有沙箱）
```

### 4.1 模型未连通：固定文案须包含

- 一句话：需要先连上大模型才能对话。
- 引导：打开「设置」→ 填写 API 地址 / Key / 模型名。
- 安抚：材料仍在本机；配置的是用户自己的接口。
- 可选：配好后直接在下方再发一句即可。

### 4.2 已连通、未选文件夹：入门策略

在约 3～5 轮内让用户明白：

1. **能做什么**（本地材料、对话办事、技能可叠加等，办事员能懂的表述）
2. **大概怎么做**（先说清任务；要动本机文件时再选一个文件夹）
3. **还有得探索**（设置、技能等点到为止）

原则：

- 先回应用户原话，再带出能力，不做强制教程口吻。
- **不硬凑满 5 轮**：用户明确要处理本地文件时，立刻软引导「打开文件夹」。
- 入门态结束条件（满足其一即可）：已选文件夹 / 用户明确「知道了、开始办事」类意图 / 已自然讲完上述三点。

### 4.3 已选文件夹之后

去掉入门策略，进入正常办事模式；对话与成果落在该文件夹沙箱内（Runtime 边界不变）。

## 5. 界面细节

### 5.1 对话区空态（尚无消息）

- 保留品牌块（名称 + 定位句）。
- 四条优势长卡片不再铺满抢视线（可缩成一行小字，或仅保留在设置「使用说明」）。
- 一句轻提示，例如：「先随便问一句，我再告诉你文书通能帮你做什么。」
- 空态**无**主题绿大按钮。

### 5.2 输入与发送

| 状态 | 输入框 | 发送 |
|------|--------|------|
| 运行时未就绪 | 可看，发送禁用 | 灰；悬停说明未就绪 |
| 运行时就绪（无论是否已选文件夹） | 可输入 | **主题绿**，可点 |
| 发送中 | 按现有逻辑 | 发送中样式 |

- 未选文件夹占位符示例：「试着问：文书通能帮我做什么？」
- 已选文件夹占位符示例：「描述要办的事…」
- 附件：未选文件夹时禁用，次要说明「处理本机文件前请先打开文件夹」（非绿）。

### 5.3 侧栏：文件夹与会话

- 标签：**当前文件夹**；未打开显示「未打开」+ 幽灵/次要「打开文件夹」。
- 已打开：文件夹名 + 「更换文件夹」。
- **第一期**：「新建对话」在未选文件夹时禁用，提示「打开文件夹后可保存对话」；未选文件夹时的聊天可不持久化或仅内存。选中后沿用现有会话列表。

## 6. 实现触点（指导实现，非本文件的任务拆分）

| 区域 | 预期改动方向 |
|------|----------------|
| `guide.ts` / 欢迎与微提示 | 文件夹口径；空态轻提示；弱化或移出四柱抢焦 |
| `ChatPanel.tsx` | 解除「必须 workspaceOpen 才能发送」；发送保持主绿；空态去主 CTA「打开文件夹」；入门/失败路径文案 |
| `SessionList.tsx` | 「当前文件夹」；打开文件夹非主绿；新建对话未开文件夹时禁用 |
| `WorkspaceTree.tsx` / 设置权限文案 | 「工作区」→「文件夹」用户文案 |
| Runtime / chat | 未选文件夹允许对话；挂入门策略；无文件夹时拒绝写/读工具；模型失败时壳层或 Runtime 返回可展示的固定引导（与「无 Key」一致体验） |

沙箱与路径越界规则**不放松**：只改变「何时要求用户选择文件夹」与「如何称呼它」。

---

## 7. 成功标准

- 新用户打开后，第一眼与第一可点主色动作落在**发送**，而非打开文件夹。
- 界面用户可见文案中不再出现「工作区」「项目文件夹」混用。
- 模型已配置时，用户随便发一句能得到自然回复，并在约 3～5 轮内建立「能做什么 / 怎么做 / 可再探索」心智。
- 模型未配置或连不通时，得到清晰固定引导进入设置配 Key，而非空白或技术堆栈。
- 未选文件夹时无法越权读写本机文件。

---

## 8. 非目标（本设计不做）

- 重做技能系统或 Runtime 工具协议。
- 多步强制 GUI 向导。
- 未选文件夹时持久化完整会话历史（可列为后续增强）。
- 把「文件夹」改回「工作区」作为用户主词。
