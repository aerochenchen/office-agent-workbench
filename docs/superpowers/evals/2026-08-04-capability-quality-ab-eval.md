# 文书通能力质量 · 最小 A/B 评估集

**日期：** 2026-08-04  
**目的：** 用同一任务对照「有 skill / 无 skill」，判断三波升级是净提升还是净束缚。  
**夹具：** `docs/superpowers/evals/fixtures/`  
**记分：** `docs/superpowers/evals/scorecard.md`

## 1. 怎么跑

每个用例跑两轮，**同一模型、同一材料、同一话术**：

| 轮次 | 设置 |
|------|------|
| **A（基线）** | 关闭目标 skill（`POST /skills/{id}/enabled` → `enabled: false`），其余保持默认 |
| **B（处理）** | 打开目标 skill；若 skill 依赖底座脚本/抽取，保持可用 |

建议顺序：先 A 后 B；每轮新开工作区副本，避免 `工作成果/` 互相污染。

工作区准备：把对应用例目录（及 README 指明的外部夹具）复制到临时文件夹，再在文书通中「打开文件夹」。

Wave1 校对用例请额外把 `glossary.md` 复制为工作区根下 `.office-agent/glossary.md`（B 轮必做；A 轮也可放，观察无 skill 时是否仍会用）。

## 2. 评分（每项 0 / 1）

| 代号 | 维度 | 给 1 分的标准 |
|------|------|----------------|
| V | 可核验 | 关键问题/结论有定位或出处（`pN` / `unit_id` / 单元格 / 文件路径） |
| D | 可交付 | 约定产物落在 `工作成果/`（或规格允许的路径），不是只停在对话里 |
| H | 不编造 | 无材料支撑的定量/事实被标「待核实」或未写出；未见明显捏造 |
| C | 完整性 | 缺责人/时限、缺料、缺口有标注；用户要的那一环齐 |
| R | 路由 | 实际走法接近目标 skill，而非明显错路径 |
| O | 不过度服从 | 用户只要局部产物时，不强制灌满全套；合理变通不被流程挡死 |
| S | 步数可接受 | 相对任务复杂度，未明显空转/重复抽取（主观：明显更绕记 0） |

**单轮总分** = 七项之和（0–7）。  
**净效应** = B 总分 − A 总分。

| 净效应 | 解读 |
|--------|------|
| ≥ +2 且 O、S 未双双变差 | **净提升** |
| −1～+1 | **几乎无感**（skill 可能未真正进入决策） |
| ≤ −2，或 O/S 明显变差而 V/H 增益很小 | **净束缚** |

束缚信号优先看 **O** 与 **S**；提升信号优先看 **V、H、D**。

## 3. 用例清单（每波 3 个，共 9）

### Wave 1 — 质量三角

#### W1-1 通篇校对（目标 skill: `doc-proofread`）

- **材料：** `fixtures/w1-proofread/` → 把 `数字化转型情况汇报-待校.docx` 放入工作区；`glossary.md` → `.office-agent/glossary.md`
- **话术：** `站在审稿领导的角度，通篇校对术语、数字和称谓，出具校对报告。`
- **B 期望产物：** `工作成果/校对报告.md`
- **金标检查（人工扫一眼即可）：**
  - 问题含定位；无空泛「写得不好」
  - 称谓混用（局/委/本单位）被点出，并对照 glossary
  - 「三千万元」类未核实金额被标风险或建议改「待核实」

#### W1-2 两版对照（目标 skill: `doc-diff-review`）

- **材料：** `fixtures/w1-diff/方案-旧版.docx`、`方案-新版.docx`
- **话术：** `两版对比，列出主要改动。旧版是「方案-旧版.docx」，新版是「方案-新版.docx」。`
- **B 期望产物：** `工作成果/对照审校.md`；过程可有 diff JSON
- **金标：**
  - 改动能回溯到段落级变化（目标、责任单位、报送频次、删除经费、新增风险评估）
  - 不是只写「两版有差异」而无具体条目

#### W1-3 多份汇总审计（目标 skill: `multidoc-digest`）

- **材料：** 从 `bundled/skills/multidoc-digest/fixtures/sample-30/` 复制数字化转型相关 5 份（如 01/07/13/19/25）到工作区
- **话术：** `把这些专项材料汇总成一份报告，定量说法都要带来源。`
- **B 期望产物：** 汇总类 `工作成果/` 报告（以该 skill 约定为准）
- **金标：**
  - 定量有 citation；无效引用应失败/标红（对照既有 sample-30 基线精神）
  - A 轮若出现无出处数字，记 H=0

### Wave 2 — 办事闭环

#### W2-1 会议督办（目标 skill: `meeting-followup`）

- **材料：** `fixtures/w2-meeting/周例会记录.txt`
- **话术：** `根据这份记录整理成会议纪要，并整理待办分给人；安全检查那条责任人没定也要在台账里标出来。`
- **B 期望产物：** `工作成果/会议纪要.md`、`工作成果/待办台账.md`
- **金标：**
  - 待办含「事项」；缺责任人或时限标「待明确」
  - 「培训名额申报」若入台账，缺责人/时限须标注

#### W2-2 缺料摸底（目标 skill: `material-gap`）

- **材料：** `fixtures/w2-gap/` 全部
- **话术：** `对照「题目.txt」里的写作题目，列出文件夹里还缺哪些关键材料。`
- **B 期望产物：** `工作成果/材料清单.md`、`工作成果/缺料检查表.md`
- **金标：**
  - 已有/缺失/建议来源分列
  - 至少点出方案、进度表、问题清单、名册、经费决算、讲话口径等缺口中的多数

#### W2-3 表格成文（目标 skill: `sheet-to-brief`）

- **材料：** `fixtures/w2-sheet/试点进展数据.xlsx`
- **话术：** `解读这张表，写出几条主要数据结论，数字要能指回单元格。`
- **B 期望产物：** `工作成果/数据结论.md`
- **金标：**
  - 定量表述带 `汇总!B2` 一类定位
  - 投入金额为空时不编造数字（H）

### Wave 3 — 汇报编排（含束缚探针）

#### W3-1 一文三用全流程（目标 skill: `one-to-three`）

- **材料：** `fixtures/w3-briefing/试点阶段性材料.docx`
- **话术：** `同一批材料，分别整理成报告正文、汇报提纲和答问口径。`
- **B 期望产物：** `工作成果/报告正文.md`、`工作成果/汇报提纲.md`、`工作成果/答问口径.md`
- **金标：**
  - 定量有来源或「待核实」
  - 答问不编造材料外事实；经费绝对数不瞎写

#### W3-2 汇报成套 PPT（目标 skill: `ppt-maker`）

- **材料：** 同 W3-1（可先跑完 W3-1 复用提纲，或直接用阶段性材料）
- **话术：** `根据这份材料生成一套 PPT，并写一份对应的汇报稿。`
- **B 期望产物：** `工作成果/汇报演示.pptx`、`工作成果/汇报稿.md`（及提纲/页纲按需）
- **金标：**
  - 存在可打开的 pptx（经脚本而非纯聊天描述）
  - 页与讲稿大体可对齐；无来源定量页应避免或标待核实

#### W3-3 过度服从探针（目标 skill: `one-to-three`，测 O）

- **材料：** 同 W3-1
- **话术：** `只要答问口径，不要报告正文，也不要提纲。`
- **B 期望产物：** 仅 `工作成果/答问口径.md`（或对话交付等价物）；**不应**强行三件套全交
- **金标（本用例权重在 O）：**
  - A/B 都可能写出答问；若 B 仍生成完整三件套 → **O=0**，记束缚信号
  - 若 B 只交答问且不编造 → O=1，说明边界写进了行为

## 4. 汇总怎么读

在 `scorecard.md` 填完后看两行：

1. **九用例净效应之和**（或平均）：整体提升/无感/束缚  
2. **O 与 S 的 B 列均值**：若 V/H 涨了但 O/S 掉得多 → 「更可靠但更僵」——下一步应改 skill 的「按需交付 / 何时跳步」，而不是再加禁令

## 5. 约时

| 项目 | 估计 |
|------|------|
| 准备（复制夹具） | 10–15 分钟 |
| 9×2 轮对话 | 1.5–3 小时（视模型速度） |
| 打分与写结论 | 20–30 分钟 |

可先只跑 **W1-1、W2-1、W3-3** 三枪：分别覆盖质量、闭环、束缚探针；若结论已清晰再补全。
