# 文书通：让机关真正「用起来」的本地办公智能体

一款办公软件值不值得推，不取决于它会不会「聊天」，而取决于它能不能把机关里真正耗人的事做完：改格式、汇材料、按模板写稿、把反复做过的流程固化下来。

**文书通**的定位很明确——**办公文书 · 智能通办**。面向机关、企事业单位的办公场景，而不是只限于政府部门。它不是挂在浏览器里的通用大模型对话框，而是装在本机、对着本地文件夹工作的办公智能体：你打开工作区，用自然语言下任务，它在受控范围内读写文件、调用脚本、产出可交付的 Word 结果。

一句话理解它：像给办公场景装了一台「会干活的助手」，而不是又开了一个「会说话的窗口」。

## 一、它解决什么问题

机关文秘、综合、业务科室每天面对的，往往不是「写一段漂亮文字」，而是三类更具体的痛：

**格式要合规。** 红头、字体、行距、标题层级，差一点就不像正式公文。人改一遍费时，改多遍容易漏。

**材料要汇总。** 几十份汇报、总结、说明散落各处，要整理成一份带出处的报告。人读得慢，出处对不上，后面核对更累。

**写法要贴近本单位。** 领导要的不是网上范文，而是「像我们单位以前那样写」：结构、语气、论证方式都要对得上历史材料。

通用聊天工具能给灵感，但很难可靠地改本地 `.docx`、很难按国标排版、很难在内网里把素材检索做成可复用流水线。文书通要补的，正是这一截：**从说到做**。

## 二、定位：办公域的 Agent，不是聊天框

市场上许多「AI 办公」产品，本质是云端对话外加一点插件。文书通走的是另一条路：

| 常见 AI 聊天 | 文书通 |
|---|---|
| 对话为主，文件是附件 | 工作区文件夹是主战场 |
| 能力主要靠模型临场发挥 | 能力可安装、可复用、可沉淀为「技能」|
| 多走公网大模型 | 对接单位内网私有模型（如 DeepSeek）|
| 结果常停在文字回复 | 结果常落成可打开、可流转的文档 |

把它想成「办公版的编程助手」会更贴切：程序员用 Agent 改代码仓库；文秘用文书通改文书工作区。底层都是：**工作区 + 多轮对话 + 工具调用 + 可扩展技能**。不同的是，文书通把领域收束在机关企事业的办公文书，并按本机工作区与单位自定模型来设计。

品牌口号里的「通办」，指的不是行政审批通办，而是：**同一套工作台，能通办多种文书事务**——排版、汇总、写作、以及把本单位特有流程做成新技能。

## 三、现在就能做什么

当前面向试用的主路径已经打通，标准能力大致包括：

**1. 公文格式排版**  
依据党政机关公文格式要求，对工作区里的 Word 进行自动化排版（页面、字体、行距、标题层级、红头相关样式等），输出带 `_formatted` 后缀的新文件，便于对比与复核。印章等仍需人工把关——产品刻意把「机器该做的」和「人必须审的」分开。

**2. 批量文档整理**  
面对几十份材料，用脚本做分块、聚类、审计等确定性重活，让大模型做摘要与主题归并，最终产出带引用锚点的汇总报告与审计报告。适合「材料很多、时间很少、还要说得出处」的场景。

**3. 办公视觉设计**  
为机关企事业 PPT 汇报按场合选用正式配色（如深蓝政务、庄重中国红等），或按单位主色生成整套视觉方案并套用到幻灯片，强调投影可读与正式场合禁忌。

**4. 创建与沉淀技能**  
若某件事你反复做，可以把它固化成新技能：规则写在说明里，重活写成脚本，验证后再安装、导出、分享。这意味着文书通不只是「预装了几个功能」，而是一个**会随着单位用法变强的能力平台**。

**5.（可选）公文写作助手**  
对配置更好的机器，可另装重量级写作技能：对本地素材做结构感知索引与检索增强，按模板与叙事规划起草报告，再衔接排版输出。重依赖不塞进默认安装包，弱机也能先用轻量能力——这是产品上的刻意选择，不是功能缩水。

日常使用路径也很直观：安装 → 配置内网模型地址与密钥 → 打开工作区文件夹 → 对话下任务 → 在技能栏启用需要的能力。Windows 提供标准安装包，适合机关常见办公环境。

## 四、为何这样设计：薄底座，厚技能

文书通最值得对外讲清楚的，不是某一两个按钮，而是它的产品结构。

**底座刻意做薄。** 桌面界面、本地运行时、会话、工作区沙箱、工具循环、技能注册、内网模型网关——这些构成「办公 Agent」的充分集。它负责稳定、可控、可审计地「跑起来」，不把所有业务逻辑焊死在核心里。

**能力放在技能里。** 排版、汇总、写作、本单位专有流程，都以可安装技能包交付。技能通常是「说明文档 + 脚本」的混合体：该讲纪律的讲纪律，该自动化的自动化。新能力优先做成技能，而不是每次都改底座。

这样做有三个直接好处：

- **装得动**：普通 4GB 内存办公机可用对话与轻量技能；需要本地向量检索的写作能力，再按工位选装。
- **换得起**：科室不同、机器不同、任务不同，不必人人扛同一个巨型安装包。
- **长得动**：单位可以把「我们就是这么写、这么汇、这么核」沉淀成自己的技能资产，而不是永远依赖厂商改版。

技术实现上，桌面壳采用现代桌面框架，本地运行时用 Python 提供工具与技能执行；大模型只走白名单内的单位私有接口；文件读写落在用户选定的工作区。对外可以简单说：**本地干活，内网问模型，能力可插拔。**

## 五、核心优势

对外可记四句话：

| 短标 | 一句解释 |
|------|----------|
| **本地可控** | 材料在文件夹里办，用什么模型自己定 |
| **轻量可跑** | 标准包轻，老旧机也能用 |
| **方法沉淀** | 好流程变成可复用技能 |
| **能力插拔** | 专项技能可安装、可分享 |

对领导，价值是**降本增效且可控**：重复性文书劳动被压缩，材料在本机工作区办理，模型接口由单位自行配置，而不是「为了方便 AI，先把材料丢上公网」。

对具体办事的人，价值是**少返工、少复制粘贴、少凭记忆硬扛**：排版一次成形、汇总带出处、写作能贴着本单位材料走；不会用的人，用说话就能启动；会的人，还能把经验写成技能留给同事。

对信息化与推广同事，价值是**叙事清晰、交付分层**：先推标准包跑通主路径，再按场景加技能；不是又一个「什么都能聊、什么都做不深」的通用助手。

更底层的判断是：机关数字化下一步，不只是「人人会用大模型」，而是「大模型能不能进入真实工作流」。文书通把切入点选在文书——频率高、规范强、结果可检查——因此试用成本低、价值可感知。
## 六、前景：从好用工具，到单位能力操作系统

如果只看今天，文书通是一款能排版、能汇总、能扩展的文书工作台。如果看远一点，它的潜力在于成为单位内部的**办公能力操作系统**：

- **技能会越装越像本单位。** 综治材料、督导汇报、专项总结、会议纪要……凡是流程稳定的，都可能下沉为技能，而不是永远停留在聊天提示词。
- **人机分工会越来越清楚。** 格式、检索、分块、审计交给脚本；判断、取舍、口径交给人与模型；签发与责任仍在人。
- **推广路径天然可复制。** 先在一个处室跑通「打开文件夹就能干活」，再把验证过的技能包带到兄弟单位；底座统一，能力按需生长。
- **商业与交付逻辑顺。** 通用零件可复用，真正值钱的是办公方法论、模板、技能与内网加固——这与「卖账号聊天」不是同一类生意。

当然，任何本地 Agent 都要持续加强权限、审计与隔离。文书通当前更适合作为**可感知价值的试用与小范围推广**起点：先让人看见「真的能办成事」，再在信任建立后把安全基线与场景技能一起做厚。

## 七、写给准备试用的人

你不需要先懂人工智能。你只需要：

1. 有一台常见 Windows 办公电脑；  
2. 有单位提供的内网模型接口；  
3. 准备一个放着真实材料的文件夹；  
4. 用一句话试试：「把这份文档按公文格式排一下」或「把这个文件夹里的材料汇总成一份带出处的报告」。

如果试用之后你的感觉是——**它不只是答得漂亮，而是把活干完了**——那文书通就站对了位置。

办公文书工作不会消失，材料也不会消失。会变化的是：谁还在手工重复，谁已经把重复交给了可靠的本地助手。文书通要争取的，正是成为后者里那个「打得开、用得上、传得开」的选择。
