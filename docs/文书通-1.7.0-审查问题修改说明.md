## 2. 对照报告一（第三版原审）逐项回应

### 2.1 H-01　绕过启动器即无鉴权，档位可被降级　【已关闭】

**原问题。** 仅当环境变量 `OFFICE_AGENT_API_TOKEN` 存在时才挂 Bearer。直接运行 `office-agent-runtime.exe` 时，`/config`、`/skills`、`/workspace`、`/chat` 对同用户进程全部开放，且档位可降为 standard，进而改 `api_base`、走公网模型。

**实际修改。** 运行时无令牌会自行生成并强制校验；`/shutdown` 同样要求令牌。封装的 local 档位从包内资源读取，不能被环境变量降级。第三轮已认定该项关闭。1.7.0 保持该实现，未回退。

**残留。** 同用户调试器可读本进程环境变量，不在产品防护承诺范围内。

### 2.2 H-02　Windows 上脚本隔离 fail-open　【已关闭（源码）；装包抽测待 1.7.0】

**原问题。** Windows 上 `sandbox_available()` 恒假，无隔离仍继续执行；`builtins.open` 补丁拦不住 `pathlib`、`io.open`、联网。技能脚本等于当前用户执行任意 Python。

**实际修改。** 隔离不可用则拒绝执行。Windows 走 AppContainer；产品执行路径注入 `OFFICE_AGENT_SCRIPT_JAIL=1`，进程内 jail 拦住 `pathlib` / `io.open` / 联网等。第三轮动态观测确认进程内层已生效。1.7.0 保持该实现。

**残留。** 见第 3 节 H-02c、H-02b。不得把「源码有路径」写成「1.7.0 安装包已端到端验证 AppContainer」。

### 2.3 M-01　安装包与自有二进制未签名　【等效管控，本版本未做代码签名】

**原问题。** `setup.exe`、`desktop.exe`、`office-agent-runtime.exe`、`uninstall.exe` 均为 Unsigned。

**实际修改。** 1.7.0 本地部署 NSIS 包仍按未签名交付。不以 Microsoft Store / Mac App Store 的平台签名顶替本 NSIS 包。

**管控。** 安装介质由使用单位在内网保管；安装前核对当场交付的 SHA256，不一致则不安装。这不是运行时漏洞，是供应链完整性。

### 2.4 M-02　构建路径、开发端口、占位符残留　【本版本未改】

**原问题。** 二进制含构建机绝对路径、开发端口、模板占位符。

**实际修改。** 1.6.0 后续包已去掉 `ws://` 开发端口与 `{{product_name}}` 占位符。1.7.0 **未**剥离 PDB/符号中的构建路径，**未**删除 `tauri.conf.json` 的 `devUrl`。第三轮所见 `localhost:1420` 残留仍在。

**说明。** 这是产物卫生，不是可调用接口，不能据此读写文件或出站。不把未剥符号写成已修复。

### 2.5 M-03　WebView2 133 且无自动更新　【版本号已关闭；无自动更新为等效管控】

**原问题。** 固定版 `133.0.3065.92`，无 Tauri updater，命中过时 Chromium。

**实际修改。** 本地部署包装钉死 `151.0.4129.107`（高于原报告所称修复线）。1.7.0 继续使用该固定版。**不开**静默自动更新，避免内网断公网环境被远程替换界面内核。

**管控。** 漏洞披露后由使用单位按 CVE 更换安装包，不要只改配置版本号而不重新拉取运行时。133 包不得再装。

### 2.6 M-04　技能校验曾是窄黑名单　【已关闭，1.7.0 对 local 再加入口拒绝】

**原问题。** 只禁少数网络库，`subprocess`、`ctypes`、`os` 等可安装；`--force` 可跳过校验。技能即本机代码通道。

**实际修改。** 导入校验已改为默认拒绝白名单（含 `subprocess`、`ctypes`、`socket`、`urllib`、`winreg` 等）。1.7.0 在此之上：**local 档位**下 `POST /skills/install` 与 `POST /skills/inspect` 直接返回 403「本地部署版本不允许安装第三方技能」。内置技能仍由封装播种与 `restore-bundled` 提供。标准包仍允许经接口导入。

### 2.7 M-05　随包脚本缺少路径边界　【已关闭，1.7.0 补 `--out`】

**原问题。** 随包脚本接受绝对路径，可把工作区外文件读入再交给模型。

**实际修改。** 产品执行路径在进隔离进程前调用 `assert_argv_within_roots`。1.7.0 另补 `bundled/skills/material-gap/scripts/inventory.py`：`--out` 必须落在当前工作区（cwd）之内，越界拒绝。

**残留。** 脱离产品、用系统 Python 直接跑这些脚本时，产品不再介入。这不是图形界面用户路径。

### 2.8 M-06　NOTICE 不能当物料清单　【本版本未改随包产物】

**原问题。** NOTICE 声明与实装漂移，缺 WebView2 再分发说明，缺 CycloneDX，部分许可文本不全。

**实际修改。** 仓库内已有 `scripts/generate_notice.sh`、`scripts/generate_sbom.py`。1.7.0 **未**把更新后的 NOTICE/SBOM 打进本地部署包产物，第三轮「包内 NOTICE 未改」的事实对本版本的已构建样品仍然成立，须在打 1.7.0 包时单独核验是否纳入构建步骤。不把「仓库有脚本」写成「安装包已带 SBOM」。

**说明。** 这是开源合规与供应链卫生，不是运行时攻击面。

### 2.9 L-01　固定端口与令牌传递　【等效管控】

**原问题。** 端口写死 8765；启动器在令牌不匹配时调 `/shutdown` 回收；令牌在子进程环境变量中。

**实际修改。** `/shutdown` 已纳入鉴权，无令牌不能关机回收。1.7.0 仍使用固定端口与环境变量传令牌。

**管控。** 运行时绑定回环；不端口转发。能调试该用户进程的人，已经能读该用户文档，不把「同用户可读环境变量」列为未修高危。

### 2.10 L-02　local 放行任意 IP　【采纳审查建议，不在软件层二次拦截】

**审查意见。** 不要写「已关闭、只允许回环/私网/链路本地」。准确表述应为：拒绝公网域名与解析为公网地址的域名；IP 字面量一律放行，以支持非 RFC1918 专网号段的部署，该取舍由使用单位评估。第三轮指出此前整改报告把未改的实现写成已关闭，与事实不符。

**实际修改。** 1.7.0 按审查建议保留原实现，并更正表述：

1. 公网云厂商域名、解析到公网的域名：拒绝。
2. IP 字面量（含 `10/8`、`192.168/16` 以及非 RFC1918 专网）一律放行。
3. **不再**在产品内做 CIDR 二次名单。内网电脑能访问哪些 IP，已由单位安全软件和网络权限配置、审查；软件层再拦一遍既挡不住专网模型，也替代不了终端出站策略。

**说明。** 承认 1.6.0 整改报告曾误写「已关闭」。1.7.0 以本条为准，请勿再用「填写 `1.1.1.1` 应失败」作为关闭标准。

### 2.11 L-03　打开旧版 Word 未禁用宏　【已关闭】

**原问题。** Windows 用 Word COM 打开 `.doc` 时未设 `AutomationSecurity`，自动宏可能执行。

**实际修改。** pywin32 与 PowerShell 两条路径均在 Open 前设置 `AutomationSecurity = 3`（强制禁用）。第三轮已认定关闭。1.7.0 保持该实现。

### 2.12 I-01　正面结论　【予以保留】

**原结论。** 反编译与沙箱动态观测未发现后门、窃密或远程控制；安装期无外联、无自启动、无服务、无计划任务；运行时业务进程连接为回环。

**实际修改。** 整改未拆除这些控制：工作区路径 `resolve` + `relative_to`、文件内容按不可信数据包裹（文本读取类工具）、权限档位、凭据环境变量剥离、审计日志脱敏、CORS 白名单、外壳 Job Object。不把「未签名、构建路径残留」重新解释成恶意软件。

## 3. 对照报告二（【1020】第三轮）逐项回应

第三轮对原审条目的复测结论，已并入第 2 节。以下仅回应第三轮**新指出或明确遗留**的问题。

### 3.1 N-01　图片通道把工作区图发给模型　【等效管控】

**原问题。** `workspace_look` 将 PNG/JPG/WEBP、Office 内嵌图、PDF 渲染页以 base64 写入模型请求。上限约 8 MiB × 4 张/轮。路径受工作区约束，字节不进会话库。图片未纳入「不可信数据」包裹。

**实际修改。** 1.7.0 **保留**看图功能，未拆除通道。路径约束与体积上限仍在。local 档位拒绝公网云厂商域名；图片请求发往使用人配置的本机或内网模型。终端实际能连哪些 IP，由单位安全软件和网络权限决定。

**未改。** 见 3.8：仍未把 `workspace_look` 纳入 `UNTRUSTED_TOOL_RESULTS`。部署上禁止为本地部署包配置公网 `api_base`。

### 3.2 N-02　提示词改为工作区材料直接读　【无需修改，不是缺陷】

**审查意见。** 系统提示不再要求「读取未附加文件必须等用户确认」，已打开文件夹中的材料可直接读。cautious/standard 的技术闸门仍在；`trust_workspace` 会自动放行。

**开发方说明。** 此项不是安全缺陷，1.7.0 **不改**提示词、不改读取闸门、不为此限制信任模式或工作区脚本。理由有二：

1. **文件夹即办理范围。** 使用人打开哪个文件夹，就是指定本轮要处理哪些材料。智能体在该文件夹内读取，是产品主路径，不是越权访问未授权文件。写入与跑脚本在谨慎/标准模式下仍要确认；「信任此文件夹」须使用人在设置中明示选择。
2. **内网单机、内网模型，不泄到互联网。** 本地部署版装在内网电脑上，材料发给使用人配置的本机或内网模型。local 档位拒绝公网云厂商域名；终端能访问哪些 IP 由单位安全软件和网络权限审查。因此「文件夹内直接读」不会把公文送到互联网。

**实际修改。** 针对 N-02：**无。** 若复测所见与第三轮样品一致（已打开文件夹内的材料可直接读），即为预期行为，请按本条关闭，不要当作未修项。

### 3.3 N-03　Office 内嵌图先整段解压再做大小检查　【无需修改，不是缺陷】

**审查意见。** 对 docx/pptx 的 zip 成员先 `read()` 再检查 8 MiB，构造高压缩比文件时可能短暂占用较多本机内存。

**开发方说明。** 此项不是本次审查应列的安全问题，1.7.0 **不改**看图读取实现。理由：

1. **审查重点是恶意代码、后门、钓鱼与数据外泄。** 解压 Office 内嵌图发生在用户主动打开的本机文件上，不安装持久化代码，不外联，不把材料送到互联网。内存用多用少，不改变信任边界。
2. **处理多种办公格式是产品可用性。** Word、PPT 本身就是 zip 容器。要把其中的图交给内网模型看，必须在本机解开对应条目。为功能可用性使用本机内存，不应列为漏洞。

**实际修改。** 针对 N-03：**无。** 请按本条关闭，不要当作未修项，也不要求改为「先读 file_size 再解压」作为准入条件。

### 3.4 P-01　送审物料、文件名与哈希不一致　【流程问题，非代码缺陷】

**原问题。** 第三轮指出送审材料、安装包文件名与哈希对不上，且出现版本错配噪声。

**实际修改。** 代码无法「修复」流程。1.7.0 送审约定：

1. 报告、安装包、SHA256 必须同一构建批次。
2. 历史 1.6.0 样品哈希与文件名只作历史记录，不再当作本版本证据。
3. 本说明在 1.7.0 安装包产出前不填写正式 SHA256，避免再次出现「报告写已修、哈希却是旧包」。

### 3.5 H-02c　AppContainer 装包端到端未验证　【验收缺口，非缺功能】

**原问题。** 第三轮动态未驱动 `/chat` 走到技能脚本，宿主进程未见 AppContainer 档案，不能证明安装包真创建容器。

**实际修改。** 1.7.0 未改隔离架构。源码在 Windows 上具备 AppContainer 路径；进程内 jail 可作过渡。正式关闭该项，须用 `-LocalDeploy` 打出的 1.7.0 包实跑 `run_skill_script`：能写工作区、不能写 `config.json`、不能连接 `1.1.1.1`。这是装包冒烟，不是再开一个功能。

### 3.6 H-02b　`--run-script` 入口本身不启用 jail　【等效管控，文档标注仍未单独立项】

**原问题。** `install_fs_jail` 仅在父进程注入 `OFFICE_AGENT_SCRIPT_JAIL=1` 时生效。直接 `office-agent-runtime.exe --run-script` 跑脚本不受进程内 jail 约束。两轮建议写入文档，均未见到独立说明。

**实际修改。** 产品图形界面执行技能脚本时会注入该环境变量并带 `--jail-root`。1.7.0 **未**让裸 `--run-script` 默认开启 jail（避免把调试入口与受保护入口 silently 混为一谈）。普通办公用户不走该入口。本修改说明即对该建议的书面回应：该入口不是受保护执行路径。

### 3.7 其它复测观察（日志、绑定、无后门）

第三轮确认运行时业务连接为回环、安装期无外联等正面结论，1.7.0 保持。诊断日志仍按审计事件脱敏策略记录，不把接口鉴权状态写进可被未授权读取的明文。若复测时见到启动器与运行时的本机日志，应以「是否含令牌、是否含工作区原文」核验，而不是以「有日志」判定为缺陷。

### 3.8 N-01 附属：图片未纳入不可信数据包裹　【本版本未改】

**原问题。** `workspace_look` 走用户消息通道，不在 `UNTRUSTED_TOOL_RESULTS` 中。图中文字可能被模型当成指令。

**实际修改。** 无。该集合仍为 `workspace_read`、`workspace_extract`、`workspace_list`、`read_skill`。这是提示注入加固项，不是出站开关。出站方面：公网域名由 local 档位拒绝；能访问哪些 IP 由内网安全策略决定。

## 5. 本地部署仍须由使用单位确认的条件

下列条件是残留风险的补偿控制，建议写入部署说明：

1. 安装介质由使用单位在内网保管，不从公网下载。
2. 安装前核对交付方提供的 SHA256，与介质不一致则不安装。
3. 模型地址拒绝公网云厂商域名。IP 字面量由使用人填写；终端能访问哪些 IP，以单位安全软件和网络权限为准。
4. 终端不出公网，或由使用单位防火墙限制该软件出站。
5. 本地档位不允许经接口安装第三方技能，仅使用随包内置技能。
6. 非 RFC1918 专网模型直接填 IP 即可。不在产品内维护第二份 CIDR 名单。
7. 工作区自定义脚本默认关闭，确需「现写现跑」时由使用人在设置中开启，并仍受脚本隔离约束。权限档位（含「信任此文件夹」）由使用人自选，不作为 N-02 的补丁。
