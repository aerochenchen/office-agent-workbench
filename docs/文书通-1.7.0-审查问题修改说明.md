## 2. 对照报告一（第三版原审）逐项回应

### 2.1 H-01　绕过启动器即无鉴权，档位可被降级　【已关闭】

**原问题。** 仅当环境变量 `OFFICE_AGENT_API_TOKEN` 存在时才挂 Bearer。直接运行运行时时接口对同用户开放，档位可降为 standard。

**对照源码。** `office_agent/__main__.py` 启动时调用 `ensure_api_token()`；鉴权中间件对除 `/health` 外的路由强制 Bearer。`/shutdown` 额外限制来源为回环。封装的 local 档位以包内 `deployment-profile` 为准，环境变量不能把 local 降为 standard。第三轮已认定关闭。1.7.0 未回退。

**残留。** 同用户调试器可读本进程环境变量，不在产品防护承诺范围内。

### 2.2 H-02　Windows 上脚本隔离 fail-open　【已关闭（源码）；装包抽测待 1.7.0】

**原问题。** Windows 上无隔离仍继续执行；技能脚本等于当前用户执行任意 Python。

**对照源码。** local 档位加载配置和 `POST /config` 均强制 `require_script_sandbox=True`。`ToolExecutor` 在隔离不可用时抛错拒绝执行。Windows 走 AppContainer；产品路径设置 `OFFICE_AGENT_SCRIPT_JAIL=1` 并带 `--jail-root`。第三轮确认进程内层已生效。1.7.0 未改隔离架构。

**残留。** 见 3.5、3.6。不得把「源码有路径」写成「1.7.0 安装包已端到端验证 AppContainer」。

### 2.3 M-01　安装包与自有二进制未签名　【等效管控】

**对照源码。** 1.7.0 本地部署 NSIS 包仍按未签名交付。不以商店平台签名顶替本 NSIS 包。完整性以当场交付的 SHA256 为准。

### 2.4 M-02　构建路径、开发端口、占位符残留　【本版本未改】

**对照源码。** `apps/desktop/src-tauri/tauri.conf.json` 仍含 `"devUrl": "http://localhost:1420"`。1.7.0 未剥离构建路径、未删除该字段。这是产物卫生，不是可调用接口。

### 2.5 M-03　WebView2 133 且无自动更新　【版本号已关闭；无自动更新为等效管控】

**对照源码。** `tauri.localdeploy.conf.json` 钉死 `FixedVersionRuntime.151.0.4129.107`。桌面工程无 updater 配置。内网按 CVE 换安装包，不开静默升级。133 包不得再装。

### 2.6 M-04　技能校验曾是窄黑名单　【已关闭，安装功能保留】

**原问题。** 技能包含可执行脚本。当时校验只禁少数网络库，`urllib` / `subprocess` / `ctypes` 可过；`--force` 还能跳过校验。这是「校验过宽」，不是「不允许有安装功能」。

**关闭依据（第三轮已认定）。** 缺陷关闭靠导入校验，不靠拆除安装口：

1. `skill_validate.py` 改为默认拒绝：未列入 `ALLOWED_IMPORT_ROOTS` 的模块不能安装；`FORBIDDEN_IMPORT_ROOTS` 含 `subprocess`、`ctypes`、`socket`、`urllib`、`winreg` 等。
2. `force_overwrite` 只用于覆盖随包旧版，不能跳过校验失败。
3. 通过校验后的脚本执行仍走 H-02 隔离（隔离不可用则拒绝执行）。安装成功写入 `skill_install` 审计。

**功能保留。** 本地部署与标准包同一套安装接口：`POST /skills/inspect`、`POST /skills/install` 对合法技能包返回 200；含进程/网络模块的包预检不通过、安装 400。随包技能仍由封装播种，`restore-bundled` 可恢复内置技能。专项方法包是产品能力，1.7.0 **不**用 403 关掉入口。

**说明。** 仓库历史中曾试验 local 下直接 403，已撤回。请勿再用「local 包安装技能应失败」作为本项关闭标准。

### 2.7 M-05　随包脚本缺少路径边界　【已关闭，1.7.0 补 `--out`】

**对照源码。** 产品调用脚本前执行 `assert_argv_within_roots`。1.7.0 另在 `bundled/skills/material-gap/scripts/inventory.py` 中校验 `--out` 解析后必须落在 cwd（工作区根）之内，越界打印错误并退出。

**残留。** 用系统 Python 直接跑这些脚本时，产品不再介入。

### 2.8 M-06　NOTICE 不能当物料清单　【本版本未改随包核验】

**对照源码。** 仓库有 `scripts/generate_notice.sh`、`scripts/generate_sbom.py`。Windows / macOS 打包脚本在 NOTICE 缺失时失败，并复制 NOTICE 进资源目录。1.7.0 安装包尚未构建，不声称包内 NOTICE/SBOM 已按本版本核验。这是供应链卫生，不是运行时攻击面。

### 2.9 L-01　固定端口与令牌传递　【等效管控】

**对照源码。** `DEFAULT_PORT = 8765`。令牌仍经环境变量交给运行时。`/shutdown` 要 Bearer，且来源须是回环。1.7.0 未改端口和传令牌方式。

### 2.10 L-02　local 放行任意 IP　【采纳审查建议】

**审查意见。** 不要写「已关闭、只允许回环/私网/链路本地」。准确表述应为：拒绝公网域名与解析为公网地址的域名；IP 字面量一律放行，以支持非 RFC1918 专网；该取舍由使用单位评估。

**对照源码（`is_intranet_model_host`）。**

1. `api.deepseek.com` 等公网云厂商域名：拒绝。
2. 普通域名：解析后须全部为回环/私网/链路本地，否则拒绝。
3. `localhost`、`.local` / `.lan` / `.intranet` 后缀：通过。
4. **任意合法 IP 字面量一律通过**（含 `10/8`、`192.168/16` 以及非 RFC1918 专网，也包括看起来像公网的地址）。
5. 产品内**没有** CIDR 二次名单。

local 档位 `load_config` 和 `POST /config` 都调用上述判定：公网域名会被清空或 400；填 IP 则接受。终端实际能否连上该 IP，由单位安全软件和网络权限决定，软件不二次拦截。

**说明。** 承认 1.6.0 整改报告曾把该项写成「已关闭」，与实现不符。1.7.0 以本条为准。请勿再用「填写 `1.1.1.1` 应失败」作为关闭标准。

### 2.11 L-03　打开旧版 Word 未禁用宏　【已关闭】

**对照源码。** `doc_io.py` 中 pywin32 与 PowerShell 两条路径均在 Open 前设置 `AutomationSecurity = 3`。第三轮已认定关闭。1.7.0 未回退。

### 2.12 I-01　正面结论　【予以保留】

**对照源码。** 工作区路径 `resolve` + `relative_to`、文本读取类工具的不可信数据包裹、权限档位、凭据密封、审计脱敏、CORS、外壳 Job Object 均仍在。不把「未签名、构建路径残留」解释成恶意软件。

## 3. 对照报告二（【1020】第三轮）逐项回应

第三轮对原审条目的复测结论，已并入第 2 节。以下回应第三轮新指出或明确遗留的问题。

### 3.1 N-01　图片通道把工作区图发给模型　【无需修改，功能保留】

**审查意见。** `workspace_look` 将工作区图、Office 内嵌图、PDF 页发给模型。

**对照源码。** 功能保留，1.7.0 未拆除。`workspace.resolve` 限制在已打开文件夹内；单张超过 8MB 不发送；每轮最多 4 张；字节不写入工具文本。发给使用人在设置中填写的模型地址。local 档位拒绝公网云厂商域名；填 IP 时能否出站，由内网安全策略决定。

这与「打开文件夹办材料」是同一条产品路径，不是后门或钓鱼通道。

**未改。** `workspace_look` 仍不在 `UNTRUSTED_TOOL_RESULTS` 中，见 3.8。

### 3.2 N-02　提示词改为工作区材料直接读　【无需修改，不是缺陷】

**审查意见。** 已打开文件夹中的材料可直接读。cautious/standard 的技术闸门仍在；`trust_workspace` 会自动放行。

**开发方说明。** 1.7.0 **不改**提示词、不改读取闸门、不为此限制信任模式或工作区脚本。

1. **文件夹即办理范围。** 使用人打开哪个文件夹，就是指定本轮要处理的材料。这是产品主路径，不是越权访问。写入与跑脚本在谨慎/标准模式下仍要确认；「信任此文件夹」须在设置中明示选择。
2. **内网电脑、本地软件、内网模型。** 材料发给使用人配置的模型。公网域名被拒；能访问哪些 IP 由单位安全软件和网络权限审查，不泄到互联网。

**对照源码。** local 默认 `permission_mode=cautious`、`allow_workspace_scripts=False`，但二者均可在设置中改（脚本开启有确认框）。`POST /config` **不**拒绝 `trust_workspace`。

### 3.3 N-03　Office 内嵌图先整段解压再做大小检查　【无需修改，不是缺陷】

**对照源码。** `_load_look_bytes` 对 docx 先 `ZipFile.read`，调用方再检查 `len(raw) > 8 * 1024 * 1024`。1.7.0 不改。

审查重点是恶意代码、后门、钓鱼与数据外泄。解开用户自己打开的 Word/PPT 是格式处理，占用本机内存不改变信任边界，不应列为漏洞，也不作为准入条件。

### 3.4 P-01　送审物料、文件名与哈希不一致　【流程问题】

1.7.0 安装包产出前本说明不填正式 SHA256。送审时报告、安装包、哈希必须同一构建批次。历史 1.6.0 哈希只作历史记录。

### 3.5 H-02c　AppContainer 装包端到端未验证　【验收缺口】

源码在 Windows 上具备 AppContainer 路径。正式关闭须用 `-LocalDeploy` 打出的 1.7.0 包实跑技能脚本：能写工作区、不能写 `config.json`、脚本进程不能连外网。这是装包冒烟，不是缺功能。

### 3.6 H-02b　`--run-script` 入口本身不启用 jail　【等效管控】

**对照源码。** `__main__.py` 遇到 `--run-script` 直接进入 `script_jail_main`，**不**设置 `OFFICE_AGENT_SCRIPT_JAIL=1`。产品图形界面跑脚本时由 `ToolExecutor` 注入该变量并带 `--jail-root`。1.7.0 有意不把调试入口与受保护入口混为一谈。普通办公用户不走该入口。本修改说明即对该建议的书面回应。

### 3.7 其它复测观察

第三轮确认运行时业务连接为回环、安装期无外联等正面结论，1.7.0 保持。若见到本机日志，应以「是否含令牌、是否含工作区原文」核验，不要以「有日志」判定为缺陷。

### 3.8 N-01 附属：图片未纳入不可信数据包裹　【本版本未改】

**对照源码。** `UNTRUSTED_TOOL_RESULTS` 仍是 `workspace_read`、`workspace_extract`、`workspace_list`、`read_skill`，不含 `workspace_look`。看图结果走用户消息中的图像通道。这是提示注入加固项，不是出站开关，1.7.0 不作为必须关闭项。

## 5. 本地部署仍须由使用单位确认的条件

1. 安装介质由使用单位在内网保管，不从公网下载。
2. 安装前核对当场交付的 SHA256，不一致则不安装。
3. 模型地址拒绝公网云厂商域名。IP 字面量由使用人填写；终端能访问哪些 IP，以单位安全软件和网络权限为准。
4. 终端不出公网，或由使用单位防火墙限制该软件出站。
5. 可安装技能，须通过导入白名单；含进程/网络模块的包不能安装。执行仍受脚本隔离约束。
6. 非 RFC1918 专网模型直接填 IP 即可。
7. 工作区自定义脚本默认关闭，设置中可开，开启后仍受脚本隔离约束。权限档位（含「信任此文件夹」）由使用人自选。
