# 文书通 · 安装验收清单（给非开发人员）

用这份清单，像试用普通软件一样验收。  
**你不需要写代码**，只要：拿到安装包 → 装到 Windows 电脑上 → 按步骤点 → 勾选「通过 / 未通过」。

技术向的打包步骤见同目录 `VERIFY-windows.md`（给会打包的人用）。

---

## 开始前准备

### 你需要有人提供

- [ ] 一个 Windows 安装文件，名字类似：`文书通_……-setup.exe`
- [ ] 一台 **Windows 10 或以上** 的电脑（最好是没装过「开发工具」的普通电脑；虚拟机也可以）
- [ ] **内网模型接口**的地址、密钥、模型名（问项目里负责配置的人；没有这些，对话测不了）
- [ ] 准备测试用的文件夹，例如桌面上建一个 `文书通测试`，里面放：
  - [ ] 至少 1 个 `.docx` 公文/材料（测排版）
  - [ ] 可选：多几个 `.docx`（测批量整理）

### 本版不要求你测的（知道即可）

- 不要求测「写作 RAG 大包」（重依赖、可选安装，本版可不验收）
- 不要求在 Mac 上做正式分发验收
- 不要求证明「脚本绝对隔离、绝对安全」——有问题记下来交给开发即可

---

## 怎么记结果

每一步勾选：

- ✅ **通过** — 和「期望看到」一致  
- ❌ **未通过** — 写明：点了什么、屏幕上出现什么、能否复现  
- ➖ **跳过** — 缺条件（例如没给 API 密钥）时用，并写原因  

建议另开一个记事本，记下：**日期、电脑系统、安装包文件名、测试人**。

## 一、安装与启动

| # | 你做什么 | 期望看到 | 结果 |
|---|----------|----------|------|
| 1.1 | 双击 `*-setup.exe`，按向导安装（当前用户即可） | 安装顺利结束，没有报错退出 | ☐ |
| 1.2 | 打开开始菜单或桌面 | 能看到应用名 **「文书通」** | ☐ |
| 1.3 | 双击打开文书通 | 窗口打开；界面大致是：中间对话、右侧「技能」 | ☐ |
| 1.4 | 看界面是否提示 Runtime / 服务离线 | **不应**一直卡在「离线/连不上」；正常应能继续操作（或明确提示去看日志） | ☐ |

未通过时：把屏幕截图发给开发，并说明是安装失败还是打开后是空白/报错。

## 三、对话主路径

| # | 你做什么 | 期望看到 | 结果 |
|---|----------|----------|------|
| 3.1 | 在输入框发一句简单话，例如：「你好，请用一句话介绍你能做什么。」 | 有回复（可带 Markdown 格式）；不是一直转圈或立刻报错 | ☐ |
| 3.2 | 若有「停止 / 取消」按钮：生成过程中点一次 | 生成停止或很快结束，界面不再假死 | ☐ |
| 3.3 | （可选）点「附件」，选工作区里的一个文件，再提问「请根据附件文件名说说这是什么材料」 | 能带上附件发送；回复里能提到该文件（不要求完美） | ☐ |

## 四、技能栏与技能管理（刚改过的交互）

| # | 你做什么 | 期望看到 | 结果 |
|---|----------|----------|------|
| 4.1 | 看右侧「技能」栏 | **只显示已启用的技能**；栏上**没有**每个技能旁边的「卸载」按钮 | ☐ |
| 4.2 | 看底栏按钮 | 文案是 **「技能管理」**（不是「导入技能」单独当主按钮） | ☐ |
| 4.3 | 点「技能管理」 | 弹出管理界面：能看到技能列表、开关、导入、卸载等 | ☐ |
| 4.4 | 在管理里把某个技能**关掉**，关闭管理界面 | 右侧栏里这个技能**消失** | ☐ |
| 4.5 | 再在管理里把该技能**打开** | 右侧栏里又出现 | ☐ |
| 4.6 | （可选）在管理里对**非必要**技能点卸载，并确认 | 有确认提示；确认后列表里没有了（预置技能慎卸；测完可让开发帮恢复） | ☐ |

## 五、真业务路径 A：公文排版

准备：工作区里有一个 `.docx`。

| # | 你做什么 | 期望看到 | 结果 |
|---|----------|----------|------|
| 5.1 | 确认右侧技能里有类似「公文排版」且为启用状态（没有就去技能管理打开） | 右栏能看到该技能 | ☐ |
| 5.2 | 在对话里说明文件，并请它按公文格式排版（可把该 docx 设为附件） | 开始处理；过程中可能出现「工具步骤」或权限确认 | ☐ |
| 5.3 | 若弹出权限确认（写文件 / 运行脚本） | 点「允许」后能继续；点「拒绝」应停住且不乱改文件 | ☐ |
| 5.4 | 任务结束后 | 有结果说明；若给出文件路径，可用「打开」或复制路径，在 Word 里打开查看 | ☐ |

## 验收怎么算「过关」

**建议「可以扩大小范围内测」的最低标准：**

- 第一部分安装启动：全部 ✅  
- 第二部分配置 + 第三部分至少 3.1：✅  
- 第四部分 4.1～4.5：✅（技能栏改造相关）  
- 第五部分排版：主路径能走完（允许小瑕疵，但不能完全不可用）  

**有一条 ❌ 也不等于整个项目失败**——把现象记清楚交给开发修，再复测该条即可。

## 和「开发在电脑里跑一下」的区别

| | 开发本机跑 | 你这份清单 |
|--|------------|------------|
| 目的 | 改代码时方便调试 | 确认**别人装上也能用** |
| 形态 | 源码 + 开发命令 | **安装包 exe** |
| 谁来做 | 开发 | 你或业务同事 |

若还没有 `setup.exe`：先让会打包的人按 `README-standard.md` / `VERIFY-windows.md` 打出安装包，再从本清单「一、安装与启动」开始。
