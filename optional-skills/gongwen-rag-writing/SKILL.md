# 公文写作 RAG — v2.0

**核心模型：BAAI/bge-small-zh-v1.5**（512 维中文向量）

**内网交付：** 模型放在本 Skill 的 `models/bge-small-zh-v1.5/`，或设置 `GONGWEN_EMBEDDING_MODEL`。Runtime 子进程默认 `HF_HUB_OFFLINE=1`，禁止联网下载。本包为 **tier=heavy**，推荐内存 ≥8GB；勿打进标准底座安装包。

---

## v2.0 关键改进

| 版本 | 分块策略 | 检索方式 | 模板分析 | 叙事意识 |
|------|---------|---------|---------|---------|
| v1.0 | 固定 800 字符 | 章节标题单查询 | 标题层级 + 句式 | ❌ 无 |
| **v2.0** | **结构感知语义单元** | **论证驱动多角度** | **句长/语气/修辞/叙事弧线** | **✅ 全局叙事规划** |

**核心哲学变化**：从「这个章节有什么素材」→「这个章节要证明什么，需要什么素材支撑」。

## 第一步：结构感知索引

通过 Office Agent 工具：

```
run_skill_script
  skill_id: gongwen-rag-writing
  script: build_index.py
  args: [<工作区内素材文件夹>]
```

索引默认写到工作区 `.office-agent/rag/gongwen-rag-writing/index.json`（可用脚本参数覆盖）。

**v2.0 核心改进（① 结构感知分块）：**

- **语义单元识别**：提取 .docx 全文结构（标题层级：一、→（一）→ 1. → (1)），以「标题 + 其所有从属段落」为原子语义单元
- **论证链保护**：同一语义单元内段落绝不拆散。不再出现「论点在 chunk A，论据在 chunk B」
- **超大单元降级**：语义单元 > 2000 字符时，按段落边界拆分子 chunk（保留父标题元数据）
- **元数据标记**：每个 chunk 附带 `has_data`（含统计数据）、`has_case`（含案例）、`has_problem`（问题表述）、`has_measure`（措施表述）标签

```
# v1.0 chunk
{"text": "（三）推进数字化转型。一是建设了... 二是...", "source": "文件1.docx"}

# v2.0 chunk  
{"text": "（三）推进数字化转型。一是建设了智能平台，二是打通数据壁垒...",
 "section_title": "（三）推进数字化转型",
 "section_level": 2,
 "paragraph_range": [12, 18],
 "has_data": true, "has_case": true, "has_problem": false,
 "tags": ["has_data", "has_case", "has_measure"]}
```

**参数：**
- `--max-chars, -m`：语义单元最大字符数（默认 2000）
- `--output, -o`：索引输出路径

## 第二步：深度模板分析

```bash
# 完整分析
run_skill_script → gongwen-rag-writing / scripts/analyze_template.py <模板.docx>

# JSON 输出（Agent 解析用）
run_skill_script → gongwen-rag-writing / scripts/analyze_template.py <模板.docx> --json

# 仅叙事弧线（简洁模式）
run_skill_script → gongwen-rag-writing / scripts/analyze_template.py <模板.docx> --narrative
```

**v2.0 新增分析维度（⑤ 深度模板分析）：**

| 维度 | 分析内容 | 写作价值 |
|------|---------|---------|
| **句长分析** | 平均句长、分布桶、风格判定 | 决定新报告的句子节奏 |
| **修辞密度** | 排比/转折/因果密度 | 复制修辞手法使用频率 |
| **语气分析** | 强义务/弱义务/建议/陈述 比例 | 保持态度一致性 |
| **叙事弧线** | 章节论证角色推断、章节间关系检测 | **③叙事规划的核心输入** |

**叙事弧线输出示例：**
```
叙事弧线类型: 经典四段式（回顾→成绩→问题→部署）
章节论证角色:
  一、2025年工作回顾 → 定调回顾
  二、主要工作成效   → 成果展示
  三、存在的问题不足 → 问题剖析
  四、2026年工作安排 → 行动部署
章节间关系:
  一 → 二: 总结→展开
  二 → 三: 转折（先扬后抑）
  三 → 四: 问题导向→对策
💡 写作建议:
  「二」→「三」为扬→抑转折，注意过渡要自然
```

## 第三步：叙事规划（Agent 主导，③ 新增）

**这是 v2.0 最重要的流程改进。** 在开始逐节写作之前，Agent 必须先完成全局叙事规划。

### 3a. 读取模板分析结果

从第二步的 JSON 输出中提取：叙事弧线类型、每个章节的论证角色、章节间关系。

### 3b. 规划新报告的叙事结构

基于模板分析，为新报告制定叙事计划。核心问题：

1. **整体叙事弧线**：模板是「回顾→成绩→问题→部署」，新报告沿用还是调整？
2. **章节呼应设计**：
   - 第一节的「总体基调」如何渗透到后续各节？
   - 第二节的「亮点成绩」在第四节「下步工作」中如何延续？
   - 第三节的「问题」在第四节中是否每个问题都有对应措施？
3. **过渡句设计**：模板中「先扬后抑」的转折用「在肯定成绩的同时，也要清醒看到……」，新报告用什么？
4. **伏笔埋设**：哪些信息需要在前面铺垫，后面才能自然引出？

### 3c. 输出叙事计划

Agent 生成一份叙事计划（中文），写入草稿文件头部，作为后续逐节写作的约束：

```markdown
## 叙事计划

### 整体弧线
经典四段式：回顾定调 → 成绩展开 → 问题转折 → 行动部署

### 章节规划
| 章节 | 论证角色 | 关键词 | 衔接上节的过渡 |
|------|---------|--------|---------------|
| 一、 | 定调回顾 | 稳中求进、成效显著 | — |
| 二、 | 成绩展开 | 创新驱动、结构优化、民生改善 | 在XX基础上，重点抓了以下工作 |
| 三、 | 问题转折 | 发展不平衡、创新能力不足 | 在肯定成绩的同时，也要清醒看到 |
| 四、 | 行动部署 | 高质量发展、数字化转型 | 针对上述问题，下一步将 |

### 呼应设计
- 第二节的「创新能力提升」→ 第四节「加大研发投入」
- 第二节的「民生短板」→ 第四节「补齐民生领域短板」
- 第三节的问题全部在第四节有对应措施

### 过渡句模板
- 回顾→成绩：「一年来，我们坚持……，实现了……」
- 成绩→问题：「在肯定成绩的同时，也要清醒看到……」
- 问题→部署：「针对上述问题，XXXX年将重点抓好以下工作」
```

**此步骤的输出写入 `write_file`，作为后续写作的约束文件。**

---

## 第四步：论证驱动逐节合成

这是 RAG 的核心环节。**不再用章节标题直接检索**，而是基于第三步的叙事计划，从多个论证角度检索。

### 4a. 多角度论证检索（② 核心改进）

```bash
# 方式 1：命令行多查询
run_skill_script → gongwen-rag-writing / scripts/search_argument.py \
  <索引路径> \
  "成绩:技术创新 突破 成果 进展" \
  "数据:研发投入 专利 增长率 占比" \
  "案例:典型企业 示范项目 成功经验" \
  --top-k 8 --json

# 方式 2：从论证计划文件读取
run_skill_script → gongwen-rag-writing / scripts/search_argument.py \
  <索引路径> --plan <论证计划.json> --json
```

**论证计划 JSON 格式：**
```json
{
  "chapter": "二、主要工作成效",
  "queries": [
    {"role": "成绩", "query": "技术创新 突破 成果 进展", "weight": 1.5},
    {"role": "数据", "query": "研发投入 专利 增长率 占比", "weight": 1.2},
    {"role": "案例", "query": "典型企业 示范项目 成功经验", "weight": 1.0},
    {"role": "问题", "query": "短板 不足 差距 瓶颈", "weight": 0.8}
  ]
}
```

**检索特色：**
- 标签奖励：查询角色与 chunk 标签匹配时自动加分（如「数据」查询匹配 `has_data` chunk +0.05）
- 自动去重：同一 chunk 被多个角度命中时合并，保留最强得分
- 按论证角色组织输出：Agent 可以直观看到「成绩素材有哪些」「数据素材有哪些」

### 4b. Agent 逐节合成

1. 读取该节的叙事计划（从第三步输出）
2. 读取该节的论证检索结果（从 search_argument.py）
3. 按模板风格撰写：
   - 套用模板的句式模式和语气特征
   - **按论证阶段组织素材**：先陈述成绩→再用数据佐证→案例说明→小结
   - 保持与前一节的过渡衔接
   - 为后一节埋下伏笔
4. 用 `write_file` 追加到输出文档

---

## 第五步：自审修订（Agent 主导）

全文草稿完成后，Agent 以「编辑」角色审读：

1. **篇幅均衡**：各章节字数比例是否与模板接近？
2. **术语一致**：同一概念前后用词是否统一？
3. **数据可信度**：引用数据是否多源交叉验证？单一来源是否标注？
4. **过渡自然性**：章节间过渡句是否生硬？参考模板的过渡模式修正
5. **叙事完整性**：第三步规划的呼应/伏笔是否全部兑现？

针对性修改后进入排版。

---

## 第六步：排版输出

按 `government-document-format` 四步：`dump` → Agent 写 `_roles.json` → `apply` → 复核。禁止跳过结构标注直接 `format_gongwen`。

```
用户: 根据 ~/Desktop/素材/ 里的 40 份文档，参照 ~/Desktop/模板/2025年度报告.docx，
      写一份 2026 年度工作报告。

Agent 执行:
  Step 1: run_skill_script(build_index.py, [<素材文件夹>])

  Step 3: Agent 读取分析结果 → 制定叙事计划 → write_file 保存计划
  Step 4: 对每个章节:
            a. terminal("...search_argument.py <索引> --plan <该章节论证计划.json> --json")
            b. Agent 阅读检索结果 + 叙事计划 → 按论证角色组织写作
            c. write_file 追加到草稿
  Step 5: Agent 自审 → 修订
  Step 6: government-document-format：dump → 标注 roles → apply
          交付: <原文件名>_formatted.docx
```

## 脚本速查

| 脚本 | 用途 | v2.0 改进 |
|------|------|----------|
| `build_index.py` | 构建 RAG 索引 | ① 结构感知语义单元分块 + 元数据标签 |

| `search_index.py` | 单查询检索（保留） | 用于简单的辅助查询 |
